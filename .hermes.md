# Hermes Agent context for KlubHub

KlubHub is a multi-product monorepo of independent music tools (DJ, Promoter, Label). This file tells agents working in this repo *which* repo-specific skills to load and *which* invariants to honor without re-deriving them.

> Repo-wide policy. Lives on `main` and applies to every agent session in this repo.

## Load this skill first

Before editing anything, agents working in this repo should load:

```bash
# The repo-specific operating procedures (Plunk contract, Compose image
# naming, Nx project name, GHCR secrets, dev/prod runtime, em dash policy,
# workflow trigger gotchas). Lives at .agents/skills/klubhub-dev/.
```

The skill is symlinked into `.claude/skills/klubhub-dev` and `.hermes/skills/klubhub-dev` so it works from any of those tools. If the symlink is missing, the skill is also at `~/.agents/skills/klubhub-dev/` after running the install command from `skills-lock.json`.

If the skill is missing entirely: **stop and read `docs/PRODUCTION.md` and `docs/SELF-HOSTING.md` first**, then proceed with caution — there is no repo-encoded safety net.

## Nx project name

This is the single most common mistake. The project is **`@dev/dj`**, not `dj`. Commands must use:

```
pnpm nx run @dev/dj:serve       # Nuxt dev server
pnpm nx run @dev/dj:build       # static site build
pnpm nx run @dev/dj:test        # site tests
pnpm nx run dj-api:serve        # Go API (Note: NOT @dev/, separate Nx project)
```

Always pass `@dev/dj`, never `dj`. The shorter form silently resolves to the wrong project (or fails to resolve).

`NX_DAEMON=false` is required for this repo's dev workflow — Nx's daemon caches go-bridge state that doesn't reflect local Compose hot-reload correctly.

## Plunk integration (newsletter)

- **Static site** (`apps/site/public/newsletter.js`) fires `POST https://next-api.useplunk.com/v1/track` with body `{ email, event: "klubhub.subscribed" }`.
- **`event` MUST be a namespaced custom event** (e.g. `klubhub.subscribed`). Do not use `contact.subscribed` — Plunk documents it as a workflow trigger option, but it does **not** fire on contact upserts created via `/v1/track`. Plunk's [waitlist recipe](https://docs.useplunk.com/recipes/waitlist) uses custom namespaced events for this exact reason.
- **Public key** ships via env injection: `PLUNK_PUBLIC_KEY` (or `_STAGING` / `_PREVIEW`) → `build.mjs` validates it's `pk_*`, not placeholder, not empty, then injects as `<meta name="plunk-public-key">`. Build fails closed if any check fails.
- **Secret key** NEVER enters the repo. Mounted at `/run/secrets/plunk_secret_key` via Docker secret; consumed via `PLUNK_SECRET_KEY_FILE` env var. The compose files wire this for both dev and prod.
- **Workflows**: Plunk UI only — there is **no MCP tool for workflow mutation**. Trigger event name is locked after the first execution, so set it correctly the first time.
- **MCP surface** (23 tools) is read-mostly. Available: templates, contacts, campaigns, segments, track-event, send-email. NOT available: workflows, executions, domain verification, sender setup.

## Image naming convention (GHCR)

Per-product image name:

| Product | Image |
|---|---|
| KlubHub DJ | `ghcr.io/lithqube/klubhub-dj-api` |
| KlubHub Promoter (future) | `ghcr.io/lithqube/klubhub-promoter-api` |
| KlubHub Label (future) | `ghcr.io/lithqube/klubhub-label-api` |

The legacy combined `ghcr.io/lithqube/klubhub-dj` package is retired; do not push to it.

Each product owns:
- its own API image
- its own Compose project name (`klubhub-dj-dev`, `klubhub-dj-prod`, future: `klubhub-promoter-*`, `klubhub-label-*`)
- its own `.local/<product>/` private state (mounted into the dev container)
- its own `.github/workflows/containers.<product>.yml` workflow file

## Compose runtime contract

Dev (`docker-compose.yml`):
- Service name is **`app`**, not `api`. (`api` was renamed to `app` for consistency with future products.)
- Local build, no image pull.
- API binds `0.0.0.0:8080` *inside* the container; mapped to host `127.0.0.1:8080:8080`.
- `SERVE_FRONTEND=false` is the default. This makes `/` and `/tracklist` return 404 — **that is correct behavior**, not a bug. Frontend runs on the host via `pnpm nx run @dev/dj:serve` (Nuxt on `:4200`), which talks to the API at `http://127.0.0.1:8080` via `NUXT_PUBLIC_API_BASE`.
- Screenshot/callback URLs into the dev frontend use `http://host.docker.internal:4200`.
- `depends_on` storage must come up *first* with `--wait`, then bootstrap, then the full stack — see `scripts/stack_setup.py`.

Prod (`docker-compose.prod.yml`):
- Standalone: uses published image `ghcr.io/lithqube/klubhub-dj-api:${IMAGE_TAG:-v1.0.0}`.
- `SERVE_FRONTEND=true` so the API container proxies the Nuxt assets at `/`.
- Internal Nuxt port 3000 is NOT published; the API's port 8080 is the only external surface.
- Distinct compose project name (`klubhub-dj-prod`) and distinct volume names — isolation from dev.
- Read `docs/PRODUCTION.md` before prod changes.

Dev overlay (`docker-compose.dev.yml`):
- Only adds the Garage admin port mapping `127.0.0.1:${GARAGE_ADMIN_PORT:-39002}:3903`. Use this only when you need to inspect the S3-compatible storage directly.

## GitHub workflow push gate

OAuth scope from `gh` refuses to create or update `.github/workflows/*` files on `lithqube/klubhub`. If you need to change a workflow file:

```bash
git remote set-url origin git@github.com:lithqube/klubhub.git
git push
```

The SSH remote bypasses the OAuth scope check. After pushing, restore the OAuth remote if you want.

## GitHub Pages build

- The `pages.yml` build job requires `environment: { name: github-pages }` to read env-bound secrets (`PLUNK_PUBLIC_KEY` etc.). Forgetting this causes silent empty-key failures.
- The build step must gate on event type: `if: github.event_name != 'pull_request'`. PR preview builds get the placeholder `pk_ci_pr_preview_only_do_not_subscribe` directly in the workflow file.
- `main` is protected with an approval gate; **force-push to main will hang**. Create a `fix/...` branch and PR instead.

## Em dash policy

- No em dashes (`—`) in recipient-facing copy: `apps/site/public/index.html`, `apps/site/emails/*.html`.
- Em dashes OK in: code comments, HTML comments, `README.md`, `docs/*.md`, `SECURITY.md`, commit messages.
- Replacement for body copy: comma + space (`, `).

## Secret handling

The Plunk SK (and any other `sk_*`, `ghcr_*`, `1password_*` tokens) must never appear in:
- conversation
- PR descriptions
- commit messages
- logs
- repo files

The PK (Plunk public key) is shipped via env injection only, never committed.

## When stuck

- Image naming → see "Image naming convention" above.
- Anything Nx-related → load the `nx-workspace` skill *before* calling nx commands.
