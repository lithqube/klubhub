# Anti Slop Audit 001 — KlubHub DJ + Promoter

**Date:** 2026-10-23
**Mode:** AFTER (audit of an already-built project)
**Scope:** `apps/dj/app` (8 pages), `apps/promoter/app` (14 pages), `libs/ui`
**Direction:** `DESIGN.md` — "The Kinetic HUD" (obsidian/cyan, 0px radius enforced, dashed schematic lines, three font registers, glass panels, corner-bracket reticles). R-37 is satisfied; direction exists.
**Antislop release:** 3.2.21 (core only)

## Verification method

Findings were not taken from source reading alone. Every HIGH and MEDIUM finding below was re-tested against the running app:

- DJ app: static build served from `apps/dj/.output/public` (build mtime 2026-10-23 17:10, newer than every source file in `apps/dj/app`, so the build is current).
- Promoter app: mock-API dev server on `:4400`, authenticated via `POST /api/v1/auth/login`.
- Keyboard reachability: runtime `element.focus()` probe — an element is unreachable only if it has a pointer cursor, cannot take focus, has no `tabindex`, no `role=button|link`, and no focusable ancestor.
- Contrast: computed from the real token values in `libs/ui/app/assets/css/kinetic.css` (dark `:root` and light `[data-theme="light"]`), not estimated.
- Loading/error states: measured by intercepting `**/api/v1/gigs**` with a 4s delay and with `route.abort('failed')`.

Four subagent audits ran in parallel as a first pass. Their claims were treated as untrusted: several were re-tested and **falsified** (see "Claims withdrawn" at the end). Everything that survives below carries a file:line plus a runtime confirmation.

## HIGH — Hard Gate

### 1. R-26 — `QUICK EXPORT` opens a post composer instead of exporting

- `apps/dj/app/pages/social.vue:35-37` — `handleQuickExport()` calls `store.openComposePanel()`
- `apps/dj/app/components/social/SocialTabs.vue:93` — the button that emits `quick-export`
- `apps/dj/app/stores/social.ts:230-232` — `openComposePanel()` sets `composePanelOpen = true`

Runtime: clicking `QUICK EXPORT` on `/social` opens the "NEW POST" compose panel (`[data-compose-panel]` present, text `NEW POST CLOSE × FEED STORY CAPTION 0 / 2200 …`). **Zero downloads triggered**, and no download, `.ics`, `.csv`, or export-pack affordance appears anywhere on the page.

Consequence: a user who clicks `QUICK EXPORT` to get their posts out is silently sent to a post composer instead. Nothing is exported, nothing says so, and the label promises an action the product does not perform.

### 2. R-27 — A failed gig fetch renders as "NO GIGS FOUND"

- `apps/dj/app/stores/gig.ts:150-153` — `catch` block only `console.error`s and filters the list; no error state is raised
- `apps/dj/app/pages/gigs.vue:205-214` — the empty state

Runtime: with `**/api/v1/gigs**` aborted, the page renders `NO GIGS FOUND` / `ADD YOUR FIRST GIG TO GET STARTED`. A regex scan for error wording (`error|failed|could not|unable`) over the full page text returned **false**.

Consequence: an API outage is presented to the user as "you have no gigs, add your first one". The user is told to create data that already exists. This is the same failure mode on every panel the four subagents flagged — `gigs.vue`, `rider.vue` attachments, `finance.vue` void/delete, promoter `bookings.vue` do-not-contact, promoter `settings.vue` org profile, promoter `events/[id].vue` and `venues/[id].vue`.

### 3. R-32 — The gig form dialog cannot be dismissed with Escape

- `apps/dj/app/components/gig/GigFormDialog.vue:434-442` — the dialog overlay; `@click.self="close"` is the only dismissal path besides the `✕` button
- `apps/dj/app/components/gig/GigFormDialog.vue:753-760` — the cancel-confirmation overlay, same construction
- `apps/dj/app/pages/finance.vue:215-253` — the void and delete confirmations, same construction

The DJ app already ships the right primitive: `apps/dj/app/utils/dialogFocus.ts` provides `useDialogFocus()` (focus the title on open, restore the opener on close) and it is wired into the finance, rider, and invoice dialogs (`EntryForm.vue`, `InvoiceCreateForm.vue`, `EntryReconciliationDialog.vue`, `InvoiceDetailSheet.vue`, `InvoiceConfirmDialog.vue`, `RiderTemplateCreateForm.vue`). The gig dialog simply was not migrated to it.

Runtime: open `ADD GIG` on `/gigs`, then press `Escape` → the fixed overlay is still present and the dialog content is still in the DOM. Focus on open stays on the `ADD GIG` trigger (`BUTTON.btn-hud btn-hud-cta`), never moving into the dialog.

Consequence: a keyboard user who opens the gig form cannot close it with Escape, and focus is never moved into the dialog, so a screen reader announces the page behind it.

### 4. R-32 — The tracklist upload zone is unreachable by keyboard

- `apps/dj/app/components/tracklist/TracklistUploadZone.vue:108-114` — `<div class="upload-zone hud-card" @click="openFilePicker">`, no `tabindex`, no `role`, no key handler
- `apps/dj/app/components/tracklist/TracklistUploadZone.vue:138-144` — the real `<input type="file">` is `class="hidden"`

Runtime: the upload zone and its inner text wrapper are the **only** pointer-cursor elements on `/tracklist` that cannot receive focus. Every other interactive element on the page resolves to a focusable ancestor.

Consequence: a keyboard-only user cannot open the file picker to import a DJ history file. The visible hint reads "OR CLICK TO BROWSE FILES", which names the mouse-only interaction.

### 5. R-32 — The social "SCHEDULE NEW ACTIVITY" card is unreachable by keyboard

- `apps/dj/app/components/social/SocialNextSlotCard.vue:23-27` — clickable `<div>`, no `tabindex`, no `role`

Runtime: on `/social`, 5 pointer-cursor elements cannot take focus, all of them the next-slot card and its children (`"+OCT 23, 2026, 19:00 SCHEDULE NEW ACTIVITY"`). The card is the primary call to action on the page.

### 6. R-25 — Daytime HUD CTA text falls below AA against the light end of its own gradient

- `libs/ui/app/assets/css/kinetic.css:843-845` — `[data-theme="light"] .btn-hud-cta { background: linear-gradient(135deg, #006875, #009EA8); }`
- `libs/ui/app/assets/css/kinetic.css:796` — `--color-on-primary: #FFFFFF` in the light theme
- `libs/ui/app/assets/css/kinetic.css:840-842` — the same gradient on `.gradient-cta`

Computed contrast, white on each gradient stop:

| Stop | Ratio | AA (4.5:1) |
|---|---|---|
| `#006875` | 6.49:1 | PASS |
| `#009EA8` | **3.25:1** | **FAIL** |

The gradient runs from `#006875` to `#009EA8` at 135°, so the label sits over a changing background. At the light end it is 3.25:1, below the 4.5:1 required for the 11–12px uppercase CTA labels these buttons use.

Consequence: in the Daytime HUD theme, the right-hand portion of every primary CTA — `SAVE PROFILE`, `CREATE MY KEY`, `START SETUP`, `+ NEW EVENT` — is hard to read. The dark theme is fine (`#0E0E0F` on `#96F8FF` = 15.77:1).

### 7. R-25 — Tertiary text at reduced opacity fails AA in both themes

`--color-tertiary` is documented as AA-compliant at 100%, and it is. The failures are all at reduced opacity, which the token comment does not cover.

| Usage | Site | Light ratio | Dark ratio |
|---|---|---|---|
| `text-tertiary/40` — ANALYTICS, AUTOMATIONS stub labels | `apps/dj/app/components/social/SocialTabs.vue:64-79` | **1.69–1.86:1** | **1.93–2.00:1** |
| `text-tertiary/70` — `.data-frag` hint lines | `apps/dj/app/components/outreach/OutreachTemplateEditor.vue:105`, `apps/dj/app/components/outreach/OutreachComposer.vue:139` | **2.69–3.34:1** | **3.11–3.72:1** |
| `text-error/80` — failed-post reason | `apps/dj/app/components/social/SocialPostCardFailed.vue:80-83` | **3.06–4.07:1** | **3.92–4.93:1** |
| `opacity: .65` — superseded invoice rows | `apps/dj/app/components/finance/InvoiceArchivePanel.vue:80, 122, 125-127` | **~3.6:1** | — |
| `opacity: .6` — revoked door devices | `apps/promoter/app/pages/events/[id]/door.vue:346-354, 421-425, 475-485` | below AA | below AA |

The `text-tertiary/40` case is the worst: 1.69:1 in light, 1.93:1 in dark. The light-theme token block already carries the precedent for fixing this kind of drift — `--color-status-archived: #A64B08` was deepened from `#B45309` with the comment "was 4.05:1 at 8px". The same treatment was never applied to the opacity-modified tertiary text.

Consequence: the two stub labels and every dimmed hint line are effectively unreadable, and in the dark theme the failure hits the readouts that carry the most operational detail.

- `apps/dj/app/utils/outreach.ts:81, 84, 87, 94, 100, 103` — the six outreach error messages

- `apps/promoter/app/components/booking/Composer.vue:124, 129`, `MatchList.vue:17`, `TemplateEditor.vue:103`

- `apps/promoter/app/components/settings/ProfileForm.vue:101`, `SealedSetup.vue:126, 138`

Runtime confirmation: all 8 DJ tab titles render the em dash (`Dashboard — KlubHub DJ` etc.). The rendered-DOM scan found the bare `—` fallback glyph in `TheStatusBar` on every DJ page, and the promoter app's rendered pages contain **no** em-dash text nodes — the promoter em dashes live in titles and conditional notices.

Note on the design system: `DESIGN.md` uses the em dash 17 times in its own prose. That is a documentation register, not a product-UI rule, so it does not license the UI copy. The em dash as a **placeholder glyph** (`—` for "no value") is a different case from the em dash as **punctuation**; the placeholders are the `TheStatusBar` values, and those read as a deliberate HUD convention. The fix for the prose and title strings is to replace the em dash with a colon, comma, or hyphen.

### 9. R-25 — Unreachable-by-keyboard controls in the promoter app

- `apps/promoter/app/components/booking/SlotList.vue:135` — slot selection is an `<li>` with `@click` and no keyboard activation
- `apps/promoter/app/components/door/Scanner.vue:153, 161-172` — declares `aria-modal` but does not move focus in or trap Tab (Escape *is* handled)
- `apps/promoter/app/components/event/EventForm.vue:209-212` — the location-privacy radios are visually hidden and their visible labels have no `:focus-within` style

Runtime: the promoter app is otherwise clean. The only pointer-cursor elements flagged on 10 promoter pages were the two `label.chip` retention radios in `/settings`, and I checked those directly — the hidden radio inside **is** focusable (`inputFocusable=true`), so the label is a valid proxy and the finding is withdrawn.

### 10. R-03 — Clipped controls at 360px in the promoter app

- `apps/promoter/app/pages/events/index.vue:34-43` — header combines a 200px search field, a non-shrinking `+ NEW EVENT` button, and the title
- `apps/promoter/app/pages/audience.vue:161-176` — three non-wrapping header actions
- `libs/ui/app/assets/css/kinetic.css:332-342` — the shared non-wrapping header row

Runtime at a 360px viewport: on `/events` the `+ NEW EVENT` anchor's right edge lands at **378px** and on `/audience` the `ADD CONTACT` button at **397px**, both inside an `overflow: hidden` ancestor (`flex-1 flex flex-col min-h-dvh overflow-hidden`). The document's `scrollWidth` stays at 360, so there is no horizontal scrollbar — **the controls are painted outside the viewport and silently cut off**. On `/audience` the contact rows (`<li>`, right edge 412px) sit in an `overflow: auto` container, which scrolls correctly.

Consequence: on a phone, the primary `+ NEW EVENT` and `ADD CONTACT` actions are partially invisible and cannot be scrolled into view. This is the one mobile finding that survived a runtime test as a genuine defect.

Note: the DJ app's `/gigs` filter row has the same non-wrapping shape (`apps/dj/app/pages/gigs.vue:136-188`, right edge 391px), but its parent is `overflow-x: auto`, so it scrolls. That is the pattern the promoter app should adopt.

### 11. R-09 — Status badges used for non-status information

- `apps/dj/app/components/outreach/OutreachMatchesList.vue:44-46` — venue names carry the `badge-archived` class
- `apps/dj/app/components/outreach/OutreachSentLog.vue:44` — EPK attachment presence carries `badge-draft`

`badge-archived` (`libs/ui/app/assets/css/kinetic.css:649-652`) renders amber (`--color-status-archived`), and `badge-draft` (`:637-640`) renders violet. Both are status vocabulary. A venue name is not an archived record, and an attached EPK is not a draft.

Consequence: color coding carries a meaning that does not apply, so a user scanning matches for archived venues, or sent requests for drafts, reads a false signal.

### 12. R-26 — The `CALENDAR` tab is a labelled stub

- `apps/dj/app/components/social/SocialTabs.vue:49-60` — the enabled tab
- `apps/dj/app/components/social/SocialTabs.vue:126-135` — the panel it renders

Runtime: clicking `CALENDAR` sets `aria-selected="true"` and renders the heading `CALENDAR VIEW` with the body text `Monthly calendar coming soon`. No calendar grid, table, or `role="grid"` element exists on the page.

This is a labeled placeholder, so it is acceptable under R-38 provided it says so, and it does. But R-24 requires nav to reflect what actually exists, and the tab is enabled rather than disabled. The neighbouring `ANALYTICS` and `AUTOMATIONS` stubs are handled correctly: they are `cursor-not-allowed` and hidden on mobile. `CALENDAR` should follow the same treatment, or ship a working calendar.

90 distinct Lucide icons are imported across 71 imports in the two apps. The Lucide look itself is a documented R-04 concern when it is the reason a set was chosen, and here it is not: `DESIGN.md` prescribes a thin-stroke schematic register, and the icons mostly serve that. The specific instances worth a look:

- `apps/dj/app/pages/index.vue:2` — `Zap` on the dashboard
- `apps/dj/app/components/outreach/OutreachTemplateEditor.vue:4` — `Star` for the default template
- `apps/promoter/app/components/booking/TemplateEditor.vue:2` — `Star` for the default template

`Gem` is doing real semantic work (a hidden track is a gem in DJ parlance), and `Star` correctly marks the default template. `Zap` on the dashboard is the weakest of the four.

### 15. R-15 — Generic empty-state CTAs

- `apps/dj/app/pages/gigs.vue:213` — `ADD YOUR FIRST GIG TO GET STARTED`

| Claim | Why withdrawn |
|---|---|
| Promoter `/settings` retention chip labels are keyboard-inaccessible | The hidden radio inside each label **is** focusable; the label is a valid proxy |

## Notes

- **Direction is present and good.** `DESIGN.md` is specific, reasoned, and self-aware about its own drift ("Tell of drift: uniform 16px gap everywhere — the system never does this on purpose"). That document is doing its job. The findings below are places where the implementation has drifted from it, not places where the direction is missing.
- **The failure mode is consistency, not aesthetics.** The DJ app's finance and invoice dialogs use `useDialogFocus()` correctly; the gig dialog does not. The finance components use `.data-frag` at 100% tertiary; the outreach components use it at 70%. The promoter app scrolls its wide tables correctly on `/audience`; its page headers do not. Each finding is a locally-correct pattern applied inconsistently, which is cheap to fix by reusing what already exists.
- **Nothing here was modified.** This is a read-only audit; no product file was changed.
