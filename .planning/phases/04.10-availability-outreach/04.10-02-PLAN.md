<objective>
Build the DJ→promoter backend: availability slots, city matching against the DJ's own promoter contacts, customizable outreach templates, and sending a booking-request email via the shared email platform with an optional EPK PDF attached. Every send is logged and linked to the email outbox; suppressions and a daily cap are enforced.

Output: migrations 033–035, the `api/internal/outreach` package, routes at `/api/v1/outreach`, wired into the DJ binary.
</objective>

# Compliance invariants (SPEC §9, v2.1)
- Only the DJ's own contacts are ever emailed (lawful source); never scraped lists
- Sender = PLUNK_FROM_EMAIL/PLUNK_FROM_NAME; non-deceptive subject; default template has an opt-out footer
- ReplyTo = the DJ's contact email so promoter replies reach the DJ's own mailbox (never the platform From); 422 when unset
- Suppressed addresses are refused (suppression is a convenience endpoint writing outreach_suppressions for a contact's email — there is NO flag on contacts); EPK attaches only on explicit per-request send
- Opt-out has an owner: the sent-log UI shows a one-click "Do not contact" next to each sent request; replies land in the DJ's inbox via ReplyTo. Inbound-reply/unsubscribe-link handling is future work, not a v1 promise
- The OSS DJ API is unauthenticated: document in SECURITY.md/SELF-HOSTING.md that /api/v1/outreach must sit behind the operator's reverse-proxy auth (same as finance email); the per-day cap bounds the damage

- SendRequest(ctx, req) — the core:
  1. Load contact (must exist, type='promoter', not deleted). **Refuse 422 (ErrNoContactEmail) when the contact has no email** — has_email=false contacts cannot be sent to. Refuse if normalized email ∈ suppressions (ErrSuppressed → 409).
  2. **ReplyTo (OUTR-06 v2.1):** resolve the DJ's contact email from `user_settings.contact_info` JSON `.email`; **refuse 422 (ErrNoReplyTo) when empty** — replies must reach the DJ's own mailbox, never the platform From. The same value feeds `{{dj_email}}`.

Commit.
  4. Resolve template (req.TemplateID or the default) → render subject/body; req.Subject/Body override when non-nil. The rendered copy is stored on the request row — the template is never mutated.
  5. If req.EPKExportID != nil: load the epk_exports row; **refuse (422) when `garage_object_key` is empty** (legacy `minio_path` rows pre-025 — SPEC §5.4 3a).   6. Build email.CreateEmailRequest{Kind: booking_request, FromEmail/FromName from config (OUTREACH_FROM_NAME overrides PLUNK_FROM_NAME), ToEmail: contact.Email, Subject, Body, **ReplyTo: dj email**}:
     - with EPK: OwnerType='epk', OwnerID=exportID, AttachmentIDs=[docID] → emailSvc.SendOwned
     - without EPK: OwnerType=OwnerTypeOutreachRequest, OwnerID=requestID → emailSvc.Send
  7. Update the request row: email_message_id, status, sent_at (sync from the returned EmailMessage).
