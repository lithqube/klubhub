## Decisions Made

- **Race-free per-tenant daily cap:** one transaction — `pg_advisory_xact_lock(hashtextextended('bookings:outreach:daily_cap:' || tenant))` → count `outreach_requests` since local-midnight in the ORG's timezone (`organizations.timezone` via `time.LoadLocation`) → refuse 429 when count ≥ max → insert the request row (status='queued') in the same transaction. Two concurrent sends cannot both pass at 49/50. Failed attempts count because the row exists before the send.
- **ReplyTo = the sending member's email:** resolved from `users.email_enc` via the principal's sub (`identity.UserIDFromSub`); device sessions and ghost users have no member email → 422 `ErrNoReplyTo`. Replies reach the member's own mailbox, never the platform From (OFFER-06 v2.1).
- **Venue withholding (OFFER-09):** `{{venue}}` renders empty for `location_mode='secret'` before `location_reveal_at` and for `'city_only'`; the city still renders.
- **Sent log survives deletions:** `talent_contact_id`/`open_slot_id`/`template_id`/`email_message_id` are `ON DELETE SET NULL`; the log row keeps status/sent_at and renders with whatever context remains.
- **Retention deletes the sent log rows:** the four personal columns are `BYTEA NOT NULL`, so UPDATE-to-NULL is impossible; DELETE matches the door_pins pattern and the schema guard's "rows deleted" acceptance. The post-event report does not read the sent log.
- **Email unavailable:** when any Plunk knob is missing, reads work and `POST /api/v1/bookings/offers` answers 503 via `ErrEmailUnavailable` (mirrors the DJ-side handler contract).

## Latent Bugs Fixed (found by this plan's tests)

- **`api/internal/platform/email/repository.go` (04.10-01):** `createTenantScoped` INSERT omitted the `id` PK column (no default) — every tenant-scoped insert would have failed with a not-null violation. 04.10-01 only tested the no-tenant guard, never a real insert. Fixed by adding `id` as the first column/value; the codec seals with `RowID = msg.ID` as AAD, so the row id must match.
- **`api/internal/promoter/bookings/repository.go`:** `matchTalentForSlot` used `t.genres && $2` (array intersection) in SELECT/ORDER BY — Postgres has no `&&` operator for arrays in that context; replaced with `(SELECT array_agg(g) FROM unnest(t.genres) AS g WHERE g = ANY($2::text[]))` and the equivalent count for ranking.
