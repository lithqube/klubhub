## Decisions Made

- **Race-free daily cap:** one transaction — `pg_advisory_xact_lock(hashtext('klubhub:outreach:daily_cap'))` → count `outreach_requests` since local-midnight → refuse 429 when count ≥ max → insert the request row (status='queued') in the same transaction. Two concurrent sends cannot both pass at 49/50. Failed attempts count because the row exists before the send.
- **Local-midnight in the sender's timezone:** the DJ side has no user-level timezone column, so the window uses the process-local timezone (`time.Local` / `TZ` env). Recorded here per plan; operators in a non-UTC TZ should set `TZ` explicitly.
- **EPK pointer reuse:** `GetCurrentByKind('epk', exportID, 'epk_pdf')` first; on conflict the existing current row is reused (the 031 immutability trigger forbids changing checksum/size/version later).
- **EPK refusal order:** the empty-`garage_object_key` refusal (422) happens AFTER cap+insert per the plan's step order — the attempt leaves a queued row and counts against the cap. Intended.
- **email_messages ownership:** with an EPK attach the outbox row is owned by `epk`/exportID (attachment ownership guard at enqueue AND retry); without EPK it is owned by `outreach_request`/row.ID.
- **Shared EmailService:** outreach and finance share one instance — same Plunk sender, same outbox table, same delivery worker.

## SPEC §15 verification (previously "not verified")

- **`epk` export key uniqueness — VERIFIED.** `api/internal/epk/service.go:321`: `key := fmt.Sprintf("epk/exports/%s.pdf", uuid.New().String())` — every export writes a NEW uuid key. A re-export never reuses a key with different bytes, so the documents pointer checksum (`checksum_sha256`) written at first attach stays valid. SPEC §5.4 3a / §15 item 10 concern resolved.

- If the stack is exposed to the internet, put `/api/v1/outreach/*` behind reverse-proxy auth (see SECURITY.md / docs/SELF-HOSTING.md).
