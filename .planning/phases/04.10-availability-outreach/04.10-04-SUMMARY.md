# Phase 04.10 Plan 04: DJ Outreach Frontend Summary

**The real DJ Outreach page lands: manage availability slots, see city-matched promoter contacts, compose + send a booking request (template picker + EPK picker + live preview + 503/409/429/422 surfaces), manage templates, review the sent log with one-click DO NOT CONTACT — store + composable + 5 components + 11 dev mocks + e2e, all gates green on chromium.**

## Performance

- **Tasks:** 5 (types/store/utils + matches+availability components, composer+template editor, sent log+page+nav, mocks+tests, E2E)
- **Verification:** `vitest run` (116 files, **1368 tests, 1 baseline skipped, all green**), `vitest run tests/outreach-*.test.ts` (**45 tests green**), `vitest run app/utils/__tests__/outreach.test.ts` (11 green), `nx run @dev/dj:build-static` (NUXT_PUBLIC_API_BASE set; **18 routes prerendered incl. `/outreach`**), `playwright test src/outreach.spec.ts --project=chromium` (**2/2 green**: slot→match→compose→send→sent log, dashboard→outreach nav)

## Decisions Made

- **Composer pre-fills the RAW template** (`Booking request: {{dj_name}} in {{city}} on {{date}}`) and renders the preview client-side; the server re-renders authoritatively at send — so the preview is a faithful preview, not the source of truth.
- **has_email=false contacts are listed and matched but never sendable** (OUTR-05 v2.1, OFFER-10 mirror). The matches component renders a `NO EMAIL` badge in place of the Compose button; the existence of a `has_email` field on the type mirrors the Go API exactly.
- **One-click DO NOT CONTACT in the sent log** (SPEC §9 v2.1 — opt-out has an owner): a reply of "stop" has a one-click path even before inbound-reply handling exists. The row's recipient email is POSTed to `/suppressions` after a confirm dialog. The same affordance is implemented on the promoter side (SentLog.vue in 04.10-05).
- **422 surfaces carry the specific reason** so the DJ can self-correct without opening docs: "this contact has no email", "set your contact email in Settings → EPK contact info so promoters can reply", "this EPK export has no file". Matches the SPEC §5.4 3a / §9 v2.1 contract.
- **Mock daily cap (50/day)** counts across long-lived dev servers; restarting `nuxt dev` resets it. CI starts a fresh server per run, so production-shaped CI never trips on this.
- **E2E repeat-safety:** the in-memory mock keeps state across runs; we used time-stamped cities (`E2E City ${Date.now()}`) so match assertions stay deterministic. Same pattern as 04.05.
- **Static build with `NUXT_PUBLIC_API_BASE`** — without it `nx run @dev/dj:build-static` fails closed (Phase 1.5.5's security guard). Set a placeholder so the build can complete; the E2E harness intercepts `/api/v1/*` via `page.route()` so the placeholder never reaches a real API.
- **Cross-project typecheck baselines:** `vue-tsc -p tsconfig.app.json` reports 352 pre-existing TS6307 / `#kui/lib/utils` errors from `libs/ui` (Phase 1.5.5's UI layer extraction). Zero new errors attributable to the 04.10-04 code paths. Verified by re-running the typecheck against the committed baseline (`git stash`, count errors, restore) — same 352.

## Deviations from Plan

- **`TheBottomNav` is unchanged.** The plan allowed adding OUTREACH only if the bottom nav had fewer than 5 items; it already has 5 (DASH/SOCIAL/EPK/GIGS/RIDER from Phase 1.5.5), so the entry was intentionally not added. Sidebar `TheNav` has it.
- **`apps/dj/server/api/v1/epk/-state.ts` + `apps/dj/server/api/v1/epk/exports.get.ts`** were created alongside the outreach mocks because the composer's EPK picker calls `GET /api/v1/epk/exports` and no Nitro mock for that route existed. The shape matches the Go `GET /api/v1/epk/exports` response (`{ data: [...] }` envelope).

## Issues Encountered

- **Static build hung on first run:** `nx run @dev/dj:build-static` blocks on `nuxt prepare` because shared UI compilation follows root TS project references into `apps/promoter`. The playbook pitfall is documented (`klubhub-dev` Pitfalls §"Prepare both Nuxt projects before snapshot DJ tests"). Fixed by running `nuxt prepare` from each app before the static build; build then completes in seconds.
- **Pre-existing typecheck noise:** the `libs/ui` cross-workspace TS6307 / `#kui/lib/utils` errors are an inherited baseline (also present at the pre-outreach SHA). Not block-listed for 04.10-04; tracked as a separate Phase 1.5.5 follow-up.

## Notes

- Firefox/Webkit browsers are not installed in this environment (the rest of the repo's E2E has the same constraint). The chromium gate is green; the manual steps for the other browsers are documented in apps/dj-e2e/src/outreach.spec.ts.
- The mocks' daily cap (50/day) is per-tenant, just like the Go handler.

## User Setup Required

- The DJ's contact email must be configured in Settings (EPK contact section → `user_settings.contact_info.email`) — sends are refused 422 without it.
- Set `OUTREACH_MAX_PER_DAY` (default 50), optionally `OUTREACH_FROM_NAME` and `EPK_PUBLIC_URL` (for `{{epk_link}}`).
- If the stack is exposed to the internet, put `/api/v1/outreach/*` behind reverse-proxy auth (see SECURITY.md / docs/SELF-HOSTING.md).
