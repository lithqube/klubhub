# Phase 04.10 Plan 05: Promoter Bookings Frontend Summary

**The real Bookings page replaces the P4 placeholder: talent book, open slots, ranked matches, template composer with live preview and venue-privacy warning, sent log with one-click opt-out — store + composable + 7 components + 19 dev mocks + e2e, all gates green**

## Performance

- **Tasks:** 5 (store/composable, slot+match components, composer+template editor, sent log+talent components+page, dev mocks+e2e)
- **Verification:** `npx vitest run apps/promoter` (36 files, 421 tests), `nx run promoter:typecheck`, `nx run promoter:lint`, `nx run @dev/promoter-e2e:lint`, Playwright `bookings.spec.ts` 5/5 — three consecutive runs against the same stateful mock server (repeat-safe)
- **Tests added:** 12 utils + 13 store + 9 mock-API + 5 e2e = 39

## Accomplishments

- **`pages/bookings.vue` (195 lines):** role gate (owner/admin/booker), loads events (upcoming) + org + talent + templates + offers + suppressions on mount; SLOTS tab = event picker → slot list → match list → composer flow; TALENT tab = contact list + editor; TEMPLATES tab = template editor; SENT tab = sent log + do-not-contact list.
- **Components (7):** `booking/SlotList` (event picker, slot CRUD form with role/genres/fee/currency), `booking/MatchList` (ranked matches, overlap genres, no-email badge without compose button), `booking/Composer` (template picker, subject/body editor pre-filled with the RAW template, live rendered preview, venue-withholding warning banner, send with 422/409/429/503 error surfaces), `booking/TemplateEditor` (CRUD + set-default + version display), `booking/SentLog` (offers newest-first with status badge + one-click DO NOT CONTACT), `talent/ContactList` (table + suppress + delete), `talent/ContactEditor` (create/edit form).
- **Store + composable:** `stores/bookings.ts` (181 lines) with per-section loading/error state; every action updates state in place (sendOffer prepends the offer, addSuppression prepends the suppression). `composables/useBookings.ts` wraps all 19 routes with the promoter error pattern.
- **Utils:** `utils/bookings.ts` — client-side `{{var}}` substitution for the preview, status→class mapping, fee/date formatting; 12 unit tests.
- **Dev mocks:** 19 Nitro routes under `server/api/v1/bookings/` + a ~360-line bookings section in `-mockDb.ts` mirroring the Go semantics: sealed-PII-free shapes identical to the API, match ranking (event genres, city case-insensitive, overlap desc then created_at desc, suppressed excluded, no-email contacts still match), daily cap (50), full error map. Seeded: 5 talent contacts (incl. no-email `tc-lena`, Hamburg `tc-finn`), 3 open slots, 2 templates (default = 00017 seed), 2 offers, 1 suppression. 9 mock-API tests.
- **E2E (`promoter-e2e/src/bookings.spec.ts`, 5 tests):** slots→matches→compose→send→sent log; OFFER-09 withheld-venue warning + empty render; talent add + one-click do-not-contact; template create + optimistic-concurrency version bump; sent-log one-click do-not-contact. All repeat-safe (unique entities per run).
- **Nav:** the Bookings entry loses its `P4` phase tag — the feature is shipped.

## Decisions Made

- **Component dirs `booking/` + `talent/` instead of the plan's `bookings/`:** Nuxt auto-import prefixes with the directory name; `bookings/BookingSlotList.vue` would register as `<BookingsBookingSlotList>`. The page uses `<BookingSlotList>`, `<BookingMatchList>`, `<BookingComposer>`, `<BookingTemplateEditor>`, `<BookingSentLog>`, `<TalentContactList>`, `<TalentContactEditor>` — all resolve. (Same convention 04.10-04 will follow with `outreach/`.)
- **Composer pre-fills the RAW template** (`Booking offer: {{event_name}} on {{date}}`) and renders the preview client-side; the server re-renders at send, so the preview is a faithful preview, not the source of truth.
- **E2E repeat-safety:** the mock server keeps in-memory state across runs, so exact-count assertions and sends to seeded contacts break on the second run. Tests create unique contacts/offers via the Playwright `request` fixture and assert lower bounds (`>= 4` matches) instead of exact counts. Verified: 3 consecutive green runs against one server.
- **Lint-driven fixes:** literal `{{…}}` inside Vue mustaches breaks the SFC parser — variable hints render via script-computed strings; `slot` prop renamed to `openSlot` (vue/no-deprecated-slot-attribute); delete actions `await` their `apiFetch<null>`.

## Notes

- The mock's daily cap (50/day) counts across runs on a long-lived dev server; CI starts a fresh server per run, so this never bites there. Restarting `nuxt dev` resets all mock state.
- Pre-existing lint warnings in `promoter-e2e/src/audience.spec.ts` (playwright/no-useless-not) left untouched — not part of this plan.
