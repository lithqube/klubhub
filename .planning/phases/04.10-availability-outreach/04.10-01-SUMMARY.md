## Decisions Made

- Type aliases instead of qualified renames: finance tests keep unqualified names and pass unchanged — the extraction is provably behavior-preserving
- `FieldSealer` callback (not a codec injected into SQL): sealing runs inside the repository's `WithTenant` tx scope, so the tenant DEK lookup (`keys.Current(ctx, tx, tenant)`) shares the transaction in 04.10-03
- `render.go` rewritten from `strings.NewReplacer` to a single-pass regex — the SPEC behavior contract ("unknown variables render as empty") wins over the plan's mechanism note
- `SendOwned`/`Send` record delivery failure on the row and return `(failedMsg, nil)` — callers assert on `msg.Status`, not `err`

## Deviations from Plan

- **render.go mechanism:** plan said "via strings.NewReplacer"; implemented as single-pass `regexp.ReplaceAllStringFunc` because the SPEC behavior contract (unknown vars → empty, no re-scan of substituted values) is not expressible with `NewReplacer`. Behavior matches SPEC §(render semantics) and §7 v2.1.
- **Test fixes during bring-up:** `codec_test.go` needed a `sealingFakeRepo` (sealer invoked inside Create) and 2-return `SealMessageFields` call sites; two new docstore integration tests needed fixes — `GetCurrent` is kind-scoped to `'general'` (test now asserts `ErrDocumentNotFound` for an invoice-only owner), and the unique-conflict wait is invisible to `pg_locks` relation filters (it is a `transactionid` wait), so the test polls `pg_stat_activity` for the in-flight INSERT instead.

## Issues Encountered

- Unique-conflict waits do not appear in `pg_locks` as relation locks — they wait on the competitor's transaction ID. The deterministic conflict test polls `pg_stat_activity` (`state='active' AND query LIKE '%INSERT INTO documents%'`) instead.
