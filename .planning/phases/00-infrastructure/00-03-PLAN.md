    **api/internal/platform/http/health.go**
    Define `HealthResponse` and `IntegrationStatus` types as shown in the interfaces block. Implement `NewHealthHandler(pool *pgxpool.Pool, store *storage.Client, cfg *config.Config) http.HandlerFunc`.

    Handler logic:
    1. Ping DB: `pool.Ping(ctx)` with 400ms context deadline. On error → integrations["database"] = {Status: "error", Message: err.Error()}; contributes to degraded.
    2. Ping MinIO: call a lightweight MinIO operation (e.g., `store.HealthCheck(ctx)` — add this method to storage.Client in Plan 01's files or add it here). On error → integrations["storage"] = {Status: "error"}.
    3. Optional integrations — check cfg fields:
       - `spotify`: if cfg.SpotifyClientID == "" → "unconfigured"; else → "ok" (no live call)
       - `discogs`: if cfg.DiscogsAPIKey == "" → "unconfigured"; else → "ok"
       - `musicbrainz`: always "ok" (no API key required, but report status)
       - `instagram`: if cfg.InstagramClientID == "" → "unconfigured"; else → "ok"
    4. Compute overall status: "healthy" if database+storage both ok; "degraded" if one optional check failed or a required check had a non-fatal issue; "unhealthy" if database or storage error.
    5. Return 200 always (the health endpoint itself is UP; the JSON describes internals). Only return 503 if the server is truly unable to respond.
    6. MigrationsOK: set true (migrations ran at startup; if we are here, they succeeded).

    **api/internal/settings/repository.go**
    Three methods on `*Repository` (wraps `*pgxpool.Pool`):
    - `GetOrCreate(ctx) (*UserSettings, error)` — SELECT WHERE deleted_at IS NULL LIMIT 1; if no row, INSERT with defaults and re-SELECT.
    - `Get(ctx) (*UserSettings, error)` — SELECT WHERE deleted_at IS NULL LIMIT 1; return ErrNotFound if no rows.
    - `Update(ctx, req UpdateSettingsRequest) (*UserSettings, error)` — UPDATE ... SET fields, updated_at=NOW() WHERE deleted_at IS NULL AND updated_at=$N. If RowsAffected() == 0, return ErrConflict.

    All queries MUST include `WHERE deleted_at IS NULL`. Use `pgx/v5` directly (not pgx/stdlib). Use `pgx.CollectOneRow` with `pgx.RowToStructByName` for scanning.

    **api/internal/settings/service.go**
    Thin wrapper: `GetOrCreate(ctx)` → calls repository. `Update(ctx, req)` → calls repository, maps ErrConflict to service-level ErrConflict (same sentinel is fine).

    **api/internal/settings/handler.go**
    - `GET /api/v1/settings` → calls service.GetOrCreate, returns 200 JSON
    - `PUT /api/v1/settings` → decodes body into UpdateSettingsRequest, calls service.Update
      - On ErrConflict → 409 JSON `{"error":"conflict","message":"Settings were modified by another request. Refresh and retry."}`
      - On success → 200 JSON with updated settings

    **api/cmd/api/main.go** — final wiring:
    1. `cfg := config.Load()` → fatal on error
    2. `log := log.New(cfg.LogLevel)`
    3. `pool := db.NewPool(ctx, cfg.DatabaseURL)` → fatal on error
    4. `sqlDB, _ := sql.Open("pgx", cfg.DatabaseURL)` → `migrations.RunMigrations(sqlDB)` → fatal on error
    5. `store := storage.New(cfg)` → `store.EnsureBucket(ctx)` → fatal on error
    6. Build dependencies: `settingsRepo`, `settingsService`, `settingsHandler`
    7. `router := http.NewRouter(cfg, pool, store, log, settingsHandler)` (http here is the internal package, not stdlib)
    8. `srv := &nethttp.Server{Addr: cfg.BindAddress + ":" + cfg.Port, Handler: router}`
    9. Log "server starting" at info level, then `srv.ListenAndServe()`

    Import alias: use `nethttp "net/http"` to avoid collision with internal `http` package. Or rename the internal package to `httpserver` — pick whichever avoids confusion.
