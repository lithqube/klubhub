## Handler (`rider/handler.go`)

```go
type Handler struct {
    svc ServiceIface  // package-internal interface, matches service signatures
}

// ServiceIface declares only the methods the handler calls.
type ServiceIface interface {
    ListTemplates(ctx) ([]*RiderTemplate, error)
    GetTemplate(ctx, id) (*RiderTemplate, error)
    CreateTemplate(ctx, in) (*RiderTemplate, error)
    UpdateTemplate(ctx, id, in) (*RiderTemplate, error)
    DeleteTemplate(ctx, id) error

    GetAttachmentByGig(ctx, gigID) (*RiderAttachment, error)
    GetAttachment(ctx, id) (*RiderAttachment, error)
    CreateAttachment(ctx, in) (*RiderAttachment, error)
    UpdateAttachment(ctx, id, in) (*RiderAttachment, error)
    DeleteAttachment(ctx, id) error

    GeneratePDF(ctx, attachmentID) (*ExportResult, error)
}

func NewHandler(svc ServiceIface) *Handler { … }

func (h *Handler) Routes() http.Handler
```

### Routes

| Method | Path | Handler func |
|--------|------|-------------|
| GET | `/templates` | `handleListTemplates` |
| POST | `/templates` | `handleCreateTemplate` |
| GET | `/templates/{id}` | `handleGetTemplate` |
| PUT | `/templates/{id}` | `handleUpdateTemplate` |
| DELETE | `/templates/{id}` | `handleDeleteTemplate` |
| GET | `/attachments/by-gig/{gigId}` | `handleGetAttachmentByGig` |
| POST | `/attachments` | `handleCreateAttachment` |
| GET | `/attachments/{id}` | `handleGetAttachment` |
| PUT | `/attachments/{id}` | `handleUpdateAttachment` |
| DELETE | `/attachments/{id}` | `handleDeleteAttachment` |
| POST | `/attachments/{id}/pdf` | `handleGeneratePDF` |

The `/attachments/by-gig/{gigId}` route is registered **before** `/attachments/{id}` so chi's static-path-first routing resolves correctly (chi matches static segments before param segments).

### Response envelopes

Match EPK's two patterns:
- Single object: `{ "data": {...} }`
- Collection: `{ "data": [{...}] }`
- Error: `{ "error": "<message>" }`
- PDF export: `{ "id": "...", "downloadUrl": "...", "createdAt": "..." }` (no `data` wrapper — matches EPK `/epk/export`)

### Status codes

- `200` — read/update/PDF success
- `201` — create success
- `204` — delete success
- `400` — invalid JSON / invalid UUID
- `404` — `ErrNotFound`
- `409` — `ErrConflict` (attachment already exists for this gig)
- `422` — `ErrInvalidInput` (name missing, etc.)
- `500` — anything else

### Request shapes

```go
type createTemplateRequest struct {
    Name       string `json:"name"`
    Technical  string `json:"technical"`
    Hospitality string `json:"hospitality"`
    Backline   string `json:"backline"`
    OtherNotes string `json:"otherNotes"`
}

type updateTemplateRequest struct {
    Name       *string `json:"name"`
    Technical  *string `json:"technical"`
    Hospitality *string `json:"hospitality"`
    Backline   *string `json:"backline"`
    OtherNotes *string `json:"otherNotes"`
}

type createAttachmentRequest struct {
    GigID      string  `json:"gigId"`       // UUID string; parse + 400 on bad
    TemplateID *string `json:"templateId"`  // optional; nil → blank
    Technical  string  `json:"technical"`
    Hospitality string `json:"hospitality"`
    Backline   string  `json:"backline"`
    OtherNotes string  `json:"otherNotes"`
}

type updateAttachmentRequest struct {
    Technical  *string `json:"technical"`
    Hospitality *string `json:"hospitality"`
    Backline   *string `json:"backline"`
    OtherNotes *string `json:"otherNotes"`
}
```

Partial updates use `*string` so empty string can mean "clear" and `null`/absent can mean "leave alone" — matches the EPK `UpsertEPKContentRequest` convention.

### Validation

- `Name` required on create (422 if empty after `strings.TrimSpace`)
- UUID parse errors → 400 with `"invalid <thing>"`
- Trim whitespace on `Name` before storing


## Mux (`rider/mux.go`)

Same shape as `finance/mux.go`:

```go
type Mux struct { templates, attachments http.Handler }

func NewMux(templates, attachments http.Handler) *Mux
func (m *Mux) ServeHTTP(w, r)
```

`ServeHTTP` strips `/api/v1/rider/` and dispatches by `parts[0]`:

- `templates` → `templates` handler
- `attachments` → `attachments` handler
- else → 404 with structured error

PDF endpoint lives at `/attachments/{id}/pdf` — that's dispatched inside the attachments handler, not the mux (chi handles it). The mux only routes by top-level subdomain.

Either handler may be `nil` → 503 `"rider handler not configured"` (matches `finance/mux.go:dispatch`).

## Handler tests (`rider/handler_test.go`)

## Contract test (`rider/contract_test.go`)

Exercises the **Mux** end-to-end (not just the templates handler) via `httptest.Server`:

```go
mux := rider.NewMux(templatesHandler, attachmentsHandler)
ts := httptest.NewServer(mux)
// make requests against ts.URL with prefix /api/v1/rider/
```

One test per top-level route to confirm the mux dispatches correctly:

| Test | URL path | Asserts routes to |
|------|----------|-------------------|
| `Mux_routes_templates_get_to_templates_handler` | `/api/v1/rider/templates/abc` | 404 from templates handler (abc doesn't exist) — proves it's the templates handler that 404'd, not the mux |
| `Mux_routes_attachments_post_to_attachments_handler` | `/api/v1/rider/attachments` (POST) | 201 |
| `Mux_unknown_resource_returns_404` | `/api/v1/rider/unknown` | 404 with `{"error":"unknown rider resource: unknown"}` |
| `Mux_nil_templates_handler_returns_503` | `/api/v1/rider/templates/abc` | 503 |
| `Mux_nil_attachments_handler_returns_503` | `/api/v1/rider/attachments` | 503 |
