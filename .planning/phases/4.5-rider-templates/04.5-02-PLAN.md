# Plan 04.5-02 — Service + PDF

## Goal

The `rider.Service` exposes the operations the HTTP layer needs: template CRUD with soft-delete, attachment CRUD with the template-copy semantics, and PDF generation that orchestrates the renderer + Garage storage + DB insert. Plus `rider/pdf.go` with the fpdf renderer matching the EPK visual style.

## Files to create

- `api/internal/rider/service.go` — business logic
- `api/internal/rider/pdf.go` — fpdf renderer
- `api/internal/rider/service_test.go` — service tests with fakes

## Service shape (`rider/service.go`)

`Service` holds three dependencies:

```go
type Service struct {
    repo    RepoIface
    storage StorageIface
    settings SettingsIface
}

type StorageIface interface {
    PutObject(ctx context.Context, bucket, key string, r io.Reader, size int64, contentType string) error
    PresignedGetObject(ctx context.Context, bucket, key string, expiry time.Duration) (string, error)
    DeleteObject(ctx context.Context, bucket, key string) error
}

type SettingsIface interface {
    GetSettings(ctx context.Context) (*settings.UserSettings, error)
}

func NewService(repo RepoIface, storage StorageIface, settings SettingsIface) *Service
```

`storage` is the same shape EPK uses (matches `epk.StorageClientAdapter`). `settings` gives the renderer the DJ name for the PDF header.

// Templates

### Template copy semantics

`CreateAttachment` is the heart of RIDER-02:

```go
func (s *Service) CreateAttachment(ctx context.Context, in CreateAttachmentInput) (*RiderAttachment, error) {
    // 1. Validate GigID exists (delegate to gig.GigReader — but the FK also catches this)
    // 2. If TemplateID is set, copy the template's current values into the new row's fields
    // 3. Otherwise, use the RiderSectionValues from the input as-is
    // 4. Hand the resolved CreateAttachmentInput to repo.CreateAttachment
    // 5. Translate FK violation on gig_id → ErrNotFound (the gig doesn't exist)
    // 6. Translate 23505 → ErrConflict (race on the partial unique index)
}
```

The FK on `gig_id` is `ON DELETE RESTRICT`. If a client posts `{gigId: "<nonexistent>"}`, Postgres returns `23503` (`foreign_key_violation`) — the service translates to `ErrNotFound` (the gig is the missing thing, not the attachment).

**Copy happens at insert time.** After `CreateAttachment` returns, updating the source template does NOT change the per-gig copy. That's the "per-gig copy, not a live link" guarantee in RIDER-02. The contract test `CreateAttachment_with_template_id_records_snapshot` in Plan 01 covers this.

When `TemplateID` is nil, the input's `RiderSectionValues` is used directly — that's the "Start from blank" / manual-fill path. All four sections default to `''` if the input omits them.

### PDF generation

`GeneratePDF` mirrors EPK's `GeneratePDF`:

1. Load attachment (404 if soft-deleted — the repo's `GetAttachment` filters on `deleted_at IS NULL`)
2. Load settings (for DJ name + accent color)
3. Render PDF into `bytes.Buffer` via `renderRiderPDF(att, settings, &buf)`
4. Compute storage key: `rider/exports/<attachment-id>.pdf`
5. `storage.PutObject(...)` — content-type `application/pdf`
6. Insert `rider_exports` row (mirror of EPK `epk_exports`)
7. Generate presigned URL (15 min expiry)
8. Return `ExportResult{ID, DownloadURL, CreatedAt}`

Wait — `rider_exports` is not in migration 026. Adding a third table now bloats the migration. **Two options:**

- **Option A**: add a `rider_exports` table now to Plan 01's migration. Pros: PDF history per attachment, matches EPK symmetry. Cons: not in RIDER-01..05; adds surface area.
- **Option B**: skip export history. Each `GeneratePDF` overwrites the previous PDF in Garage. Pros: minimal. Cons: no download history on the attachment.

RIDER-04 says "User can export the per-gig rider as a PDF". It does not require history. **Choose Option B for v1.** If the user wants history later, it's a small additive migration.

This is a deliberate scope cut. Document it in the PLAN summary so the user can override before implementation.

## PDF renderer (`rider/pdf.go`)

Pure Go fpdf renderer, same dependency as EPK (`codeberg.org/go-pdf/fpdf`). White A4 portrait, 20mm margins.

Structure (top to bottom):

```
┌─────────────────────────────────────────────────┐
│ <DJ NAME UPPERCASE>                  (Helvetica B 18) │
│ ─────────────────────────────── (accent rule, 0.8mm) │
│                                                 │
│ <Venue Name> — <City, Country>      (Helvetica 11)  │
│ <Long date — e.g. "Saturday, 14 March 2026">      │
│ ─────────────────────────────────── (rule 0.3mm) │
│                                                 │
│ TECHNICAL                       (Helvetica B 11) │
│ ─────                                            │
│ <technical text, MultiCell, 5mm line height>     │
│                                                 │
│ HOSPITALITY                                      │
│ ─────                                            │
│ <hospitality text>                               │
│                                                 │
│ BACKLINE                                         │
│ ─────                                            │
│ <backline text>                                  │
│                                                 │
│ OTHER NOTES                                      │
│ ─────                                            │
│ <other_notes text>                               │
│                                                 │
│ ───────────────────────────────────── (hairline)  │
│ Generated by KlubHub DJ            (Helvetica I 8) │
└─────────────────────────────────────────────────┘
```

Section headings: dark ink (RGB 26/26/26, matching EPK), accent rule underneath. Rules use accent color from `settings.DefaultColors["primary"]` (fallback `#96F8FF`).

Skip sections where the text is whitespace-only (`isBlank(s) string` helper — already in `epk/pdf.go`; **duplicate locally, don't import across packages**). Sections render in fixed order: TECHNICAL → HOSPITALITY → BACKLINE → OTHER NOTES.

Footer: "Generated by KlubHub DJ" in italic Helvetica 8, accent-colored.

Page break: not relevant for a single-section rider; `SetAutoPageBreak(true, 20)` matches EPK.

The `renderInline` / `tr` helpers from EPK aren't reused — the rider PDF is plain text only (no Markdown). Section text is fed directly through `tr(content)` and `MultiCell(0, 5, …)`.

Renderer signature:

```go
func renderRiderPDF(
    att *RiderAttachment,
    venueName, venueCity, venueCountry string,
    gigDate time.Time,
    userSettings *settings.UserSettings,
    buf *bytes.Buffer,
) error
```

`venueName`, `venueCity`, `venueCountry`, `gigDate` are passed in by the service — the renderer doesn't query the gig module (keeps the package boundary clean). The service layer fetches these via a `gig.GigReader.GetGig(ctx, att.GigID)`.

If the gig is not found (404 from `gig.ErrNotFound`), `GeneratePDF` returns `ErrNotFound` — but realistically the FK guarantees the gig exists as long as the attachment exists. Edge case for completeness.
