    Create `apps/dj/app/components/tracklist/` directory and start with the two most independent components.

    **TracklistUploadZone.vue:**
    Extract the upload section from tracklist.vue (the drag-and-drop area, file picker button, and upload error display). This component:

    - Error display: `text-error font-terminal` with `shadow-glow-error` container

    Extract the past tracklists section. This component:
    - Reads `useTracklistStore().pastTracklists` and `useUiStore().pastTracklistsLoading/Error`

    - Renders past tracklists using shadcn-vue Table with alternating row backgrounds (bg-surface-container / bg-surface-container-low)
    - Each row has an "Open" button and a "Delete" button using shadcn-vue Button
    - Delete triggers shadcn-vue Dialog confirmation before calling `deleteTracklist()`
    - No divider lines in the table — use alternating backgrounds only
    - Empty state: `text-tertiary font-terminal tracking-terminal uppercase text-center` with glass-panel wrapper

    Create the remaining three feature components.

    **TracklistEditor.vue:**
    Extract the track editing table from tracklist.vue. This component:
    - Reads `tracks` and `tracklist` from `useTracklistStore()` via storeToRefs
    - Reads `editLoading/editError` from `useUiStore()` via storeToRefs
    - Inline editing: clicking a cell makes it an `<Input>` (shadcn-vue); blur/Enter calls `updateTrack()` composable + updates tracks in store

    - `abortController` for in-flight requests is managed inside this component (not exposed to store)
    - Warning display: shows `warnings` from useTracklistStore with `text-error` styling
    - Loading state: show skeleton rows or loading indicator when `editLoading` is true

    **TracklistCustomizer.vue:**
    Extract the design customization panel. This component:
    - Reads/writes `preset, bgMode, bgValue, visibleFields, maxTracks, trackRangeStart, trackRangeEnd, logoPath, logoPosition, customPlaceholderPath` from `useSettingsStore()` via storeToRefs
    - Preset selector: shadcn-vue Select or Tabs for 5 presets
    - Background mode: radio-style buttons (solid / upload / mosaic)
    - Visible fields: checkbox-style toggles for each field
    - Track range: min/max number inputs when tracklist exceeds maxTracks
    - Logo upload: file input + position selector (4 options)
    - On any change, calls `$fetch` to persist to `/api/v1/settings` (same pattern as existing tracklist.vue)
    - Panel styled as `glass-panel` with `font-terminal tracking-terminal` labels

    **TracklistExporter.vue:**
    Extract the export section. This component:
    - Reads `exportLoading/exportError` from `useUiStore()` via storeToRefs
    - Reads `tracklist` from `useTracklistStore()` via storeToRefs
    - Reads settings from `useSettingsStore()` via storeToRefs
    - "Export Story" button (1080×1920): calls `generateImage({ format: 'story', ... })` composable
    - "Export Square" button (1080×1080): calls `generateImage({ format: 'square', ... })`
    - "Export Both" button: triggers both sequentially
    - Buttons disabled + show spinner when `exportLoading` is true
    - Error display with `text-error shadow-glow-error` on `exportError`
    - All buttons use primary Button variant (gradient-cta)

  <name>Task 3: Rewrite tracklist.vue as thin layout page</name>
  <files>apps/dj/app/pages/tracklist.vue</files>
  <action>
    Replace tracklist.vue with a thin layout page (≤80 lines) that:

    1. Initializes Pinia stores on mount:
       - `useSettingsStore().loadFromApi()` to populate settings
       - `useTracklistStore()` to load pastTracklists (calls listTracklists in the history component)
    2. Reads `step` from `useUiStore()` to show upload zone vs. edit layout
    3. Uses responsive layout with Tailwind breakpoints:
       - Upload step: centered upload zone, history below
       - Edit step: `lg:grid lg:grid-cols-2 lg:gap-6` side-by-side (customizer+exporter left, preview right on lg+; stacked on mobile)
    4. Imports and composes the 5 feature components
    5. Imports and renders TrackcardPreview (passing store refs as props)
    6. Zero business logic — no API calls, no direct refs, no computed properties
    7. Uses `<ClientOnly>` around any component with potential SSR issues

    Example layout structure:
    ```vue
    <script setup lang="ts">
    const settingsStore = useSettingsStore()
    const tracklistStore = useTracklistStore()
    const uiStore = useUiStore()
    const { step } = storeToRefs(uiStore)
    const { tracklist, tracks } = storeToRefs(tracklistStore)
    const { djName, logoPath, logoPosition, preset, bgMode, bgValue, visibleFields,
            maxTracks, trackRangeStart, trackRangeEnd, customPlaceholderPath } = storeToRefs(settingsStore)

    onMounted(async () => {
      await settingsStore.loadFromApi()
    })
    </script>

    <template>
      <div class="bg-surface min-h-screen p-4 lg:p-8">
        <!-- Upload step -->
        <template v-if="step === 'upload'">
          <TracklistUploadZone />
          <TracklistHistory class="mt-8" />
        </template>

        <!-- Edit step -->
        <template v-else>
          <div class="lg:grid lg:grid-cols-2 lg:gap-8">
            <div class="space-y-6">
              <TracklistEditor />
              <TracklistCustomizer />
              <TracklistExporter />
            </div>
            <div class="hidden lg:block">
              <TrackcardPreview
                v-if="tracklist"
                :tracklist :tracks :djName :logoPath :logoPosition
                :preset :bgMode :bgValue :visibleFields
                :maxTracks :trackRangeStart :trackRangeEnd :customPlaceholderPath
              />
            </div>
          </div>
        </template>
      </div>
    </template>
    ```
