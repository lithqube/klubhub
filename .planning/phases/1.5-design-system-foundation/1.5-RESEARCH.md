## Summary

Phase 1.5 installs a three-part frontend stack (Tailwind CSS v4, shadcn-vue, Pinia) into an existing Nuxt 4 monorepo app that currently has no design system, no state management, and two monolithic Vue files totaling 1,763 lines. The phase is frontend-only — no backend changes.

**Key technical finding:** Tailwind v4 for Nuxt 4 uses `@tailwindcss/vite` (a Vite plugin) rather than the `@nuxtjs/tailwindcss` module. The module approach still works via `@nuxtjs/tailwindcss` v7, but the official Tailwind docs recommend the Vite plugin for Nuxt 4. Both paths are valid; `@tailwindcss/vite` is simpler and more canonical for v4.

In Tailwind v4, the `tailwind.config.ts` file is replaced by a CSS `@theme` block inside the main CSS file. All design tokens (colors, shadows, fonts, border-radius) are defined as CSS custom properties under `@theme`, which automatically generates corresponding utility classes. This is a substantial authoring difference from v3.

shadcn-vue components are installed via CLI into `app/components/ui/` and auto-imported by Nuxt. They are copied, not dependency-linked, so direct style modification is expected. The `cn()` utility (clsx + tailwind-merge) is the standard composition tool. Toast requires a `<ClientOnly>` wrapper in Nuxt to prevent SSR hydration mismatches.

Pinia via `@pinia/nuxt` provides auto-import of `defineStore`, `storeToRefs`, and `acceptHMRUpdate`. The 27 local refs in tracklist.vue map cleanly to three stores: tracklist CRUD state, settings/customization state, and UI state (loading, errors, step).

**Primary recommendation:** Use `@tailwindcss/vite` (not `@nuxtjs/tailwindcss`) for Tailwind v4 + Nuxt 4. Define all tokens in `@theme` block in `app/assets/css/styles.css`. Install shadcn-vue via `shadcn-nuxt` module + CLI. Install Pinia via `@pinia/nuxt`. Migrate stores before decomposing components to avoid circular dependency issues.

### Pattern 2: Pinia Setup Store (Composition API style)
**What:** Stores defined as setup functions — closer to `<script setup>` components
**When to use:** All three stores in this phase use this pattern

```typescript
// Source: https://pinia.vuejs.org/core-concepts/
// apps/dj/app/stores/tracklist.ts
import { defineStore } from 'pinia'

export const useTracklistStore = defineStore('tracklist', () => {
  // State — equivalent to data()
  const step = ref<'upload' | 'edit'>('upload')
  const tracklist = ref<Tracklist | null>(null)
  const tracks = ref<Track[]>([])
  const warnings = ref<ParseWarning[]>([])
  const uploadFile = ref<File | null>(null)
  const uploadFilename = ref<string>('')
  const uploadFileSize = ref<string>('')
  const abortController = ref<AbortController | null>(null)

  // Getters — equivalent to computed
  const trackCount = computed(() => tracks.value.length)

  // Actions — regular functions
  function reset() {
    step.value = 'upload'
    tracklist.value = null
    tracks.value = []
    warnings.value = []
  }

  return {
    step, tracklist, tracks, warnings,
    uploadFile, uploadFilename, uploadFileSize, abortController,
    trackCount,
    reset,
  }
})
```

**In components:**
```typescript
// Extract reactive refs without losing reactivity
const store = useTracklistStore()
const { step, tracklist, tracks } = storeToRefs(store)
// Actions accessed directly (not via storeToRefs)
store.reset()
```

### Anti-Patterns to Avoid

- **`@nuxtjs/tailwindcss` with Tailwind v4:** The v6 module uses Tailwind v3; v7 adds v4 support but requires explicit pinning. Use `@tailwindcss/vite` instead.
- **`tailwind.config.ts` with Tailwind v4:** v4 ignores JS config files. All tokens go in `@theme` in CSS.
- **Importing Toaster outside `<ClientOnly>`:** Will cause SSR hydration mismatch for Toast component.
- **Destructuring store properties without `storeToRefs()`:** Destroys reactivity — `const { step } = store` breaks; use `const { step } = storeToRefs(store)`.
- **Using localStorage in Pinia state directly:** Causes SSR hydration mismatch; wrap in `if (process.client)` or use `pinia-plugin-persistedstate`.
- **Adding rounded corners to shadcn-vue components:** shadcn-vue uses `rounded-*` classes internally. Setting `--radius: 0px` in `@theme` overrides them globally — do not add individual `rounded-none` to every component.
- **Google Fonts CDN link in TrackcardPreview.vue:** Must be removed as part of this phase (DSYS-07). Currently TrackcardPreview loads Noto Sans from CDN.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Class name merging | Custom class logic | `cn()` from clsx + tailwind-merge | Handles Tailwind specificity conflicts, conditional classes, array input |
| Accessible dialog/modal | Custom `<dialog>` | shadcn-vue Dialog (Radix Vue) | Focus trap, ARIA, keyboard dismiss, portal rendering |
| Accessible dropdown | Custom positioned div | shadcn-vue Dropdown (Radix Vue) | Keyboard nav, ARIA roles, collision detection |
| Toast/notification system | Custom overlay system | shadcn-vue Toast + useToast | Queue management, ARIA live region, dismissal timing |
| Accessible tabs | Custom state + styling | shadcn-vue Tabs (Radix Vue) | ARIA tablist/tab/tabpanel roles, keyboard nav |
| Component variant system | if/else class strings | `class-variance-authority` (cva) | Type-safe variants, composable, default handling |
| SSR-safe store state | Manual hydration | Pinia + @pinia/nuxt | Serialization, XSS protection, Nuxt DevTools integration |

**Key insight:** The entire point of shadcn-vue is that these components contain hundreds of hours of accessibility work (Radix Vue) plus sensible defaults. Overriding the visual styling (colors, shadows, borders) is expected and documented. Re-implementing the behavior is a trap.

## Common Pitfalls

### Pitfall 1: Tailwind v4 @theme Namespace Mismatch
**What goes wrong:** Custom color named `surface` generates no utilities because `--color-surface` is the required namespace, not `--surface`.
**Why it happens:** In v4, only variables matching `--color-*`, `--shadow-*`, `--font-*`, etc. namespaces generate utilities.
**How to avoid:** Always use the full namespace: `--color-surface: #0E0E0F` not `--surface: #0E0E0F`.
**Warning signs:** Running `bg-surface` gives no background; inspect element shows no CSS variable.

### Pitfall 2: shadcn-vue Components Using Hardcoded `rounded-*`
**What goes wrong:** After setting `--radius: 0px`, some components still show rounded corners because they use explicit `rounded-md` not `rounded` (which maps to the variable).
**Why it happens:** shadcn-vue uses `rounded-md` (0.375rem) in some components, not `rounded` which would use the CSS variable.
**How to avoid:** After install, grep installed component files for `rounded-` and replace with `rounded-none` or remove. Setting `--radius: 0px` handles `rounded` but not `rounded-md`.
**Warning signs:** Dialog, Card, Input still showing slight curves after `--radius: 0`.

### Pitfall 3: Toast SSR Hydration Mismatch
**What goes wrong:** Server renders without Toaster; client mounts it; Vue throws hydration warning or blank flash.
**Why it happens:** Toast uses portals and client-only DOM APIs.
**How to avoid:** Wrap `<Toaster />` in `<ClientOnly>` in app.vue. This is documented in shadcn-vue Nuxt guide.
**Warning signs:** Console hydration warning mentioning `Toaster` or toast-related DOM nodes.

### Pitfall 4: backdrop-filter Not Working
**What goes wrong:** Glass panels show no blur effect despite correct classes.
**Why it happens:** `backdrop-filter` requires the element to have a transparent or semi-transparent background AND parent elements must not have `overflow: hidden`.
**How to avoid:** Ensure parent containers don't clip; use `bg-surface-variant/60` (with opacity) not opaque backgrounds. Test in Chrome — webkit prefix may be needed for older Safari.
**Warning signs:** Glass panels look solid rather than frosted.

### Pitfall 5: Pinia Store Not Available in Nuxt Plugin/Middleware
**What goes wrong:** `useSettingsStore()` throws "No active Pinia" error when called outside `<script setup>`.
**Why it happens:** Pinia stores require an active Pinia instance (Vue app context). This is not available at module scope.
**How to avoid:** Only call `useStore()` inside `<script setup>`, lifecycle hooks, or Nuxt composables. Use `const pinia = usePinia()` in Nuxt plugins.
**Warning signs:** Error: "getActivePinia() was called with no active Pinia".

### Pitfall 6: TrackcardPreview Import Confusion After Decomposition
**What goes wrong:** After decomposing TrackcardPreview into `trackcard/` sub-components, the Playwright screenshot API route (`server/api/screenshot/tracklist/[id].get.ts`) renders the original full component via a specific import path.
**Why it happens:** The Playwright route captures a specific URL/component combo for image generation.
**How to avoid:** Keep `app/components/TrackcardPreview.vue` as the thin orchestrator that imports from `trackcard/`. Do not rename or move the file — the Playwright pipeline imports it by path.
**Warning signs:** Generated images look wrong or show decomposed sub-components in isolation.

### Pitfall 7: Font File Names Must Match @font-face src
**What goes wrong:** Font family not applied in browser despite correct Tailwind class.
**Why it happens:** Mismatch between the filename in `public/fonts/` and the path in `@font-face src: url()`.
**How to avoid:** Download variable fonts first, verify exact filenames, then write `@font-face` declarations.
- Space Grotesk variable: `SpaceGrotesk[wght].woff2` (from github.com/floriankarsten/space-grotesk)
- Inter variable: `Inter[slnt,wght].woff2` (from GitHub rsms/inter or fontsource)
- Manrope variable: `Manrope[wght].woff2` (from GitHub)
**Warning signs:** Network tab shows font file 404; browser falls back to system font.

## State of the Art

| Old Approach | Current Approach | When Changed | Impact |
|--------------|------------------|--------------|--------|
| tailwind.config.ts | `@theme` block in CSS | Tailwind v4 (2025) | No JS config file; CSS-only token definition |
| `@tailwind base/components/utilities` | `@import "tailwindcss"` | Tailwind v4 | Single import directive |
| PostCSS plugin for Tailwind | `@tailwindcss/vite` Vite plugin | Tailwind v4 | Faster, no PostCSS pipeline |
| Vuex | Pinia | Vue ecosystem ~2022 | Pinia is now official Vue state management |
| Options-style Pinia stores | Setup-style stores | Pinia v2+ | Composition API style, more flexible |

**Deprecated/outdated:**
- `tailwind.config.ts` for Tailwind v4 projects: The file is ignored by Tailwind v4. Tokens live in CSS.
- `@tailwind base; @tailwind components; @tailwind utilities;` directives: Replaced by `@import "tailwindcss"`.
- `@nuxtjs/tailwindcss` v6: Uses Tailwind v3. v7 adds v4 support but requires explicit version pin.

## Open Questions

1. **shadcn-vue CLI init with Tailwind v4 CSS-only config**
   - What we know: `npx shadcn-vue@radix init` asks for tailwind config file path; Tailwind v4 has no config file
   - What's unclear: Whether the CLI handles CSS-only configs gracefully or requires workaround
   - Recommendation: Run `npx shadcn-vue@radix init` and answer with the CSS file path; if CLI fails, create `components.json` manually (format documented above) and skip `init`

2. **Fontsource vs. manual woff2 download**
   - What we know: CONTEXT.md specifies `public/fonts/*.woff2` (locked decision for raw files)
   - What's unclear: Whether Fontsource package approach generates the same result as manual download
   - Recommendation: Download from official GitHub repositories (Space Grotesk from floriankarsten, Inter from rsms, Manrope from sharanda) to honor the locked decision of `public/fonts/*.woff2`

3. **TrackcardPreview Playwright screenshot compatibility after decomposition**
   - What we know: Playwright screenshot API renders the tracklist page and captures TrackcardPreview; decomposition must keep TrackcardPreview.vue as the thin orchestrator at the same path
   - What's unclear: Whether the Playwright route targets a URL or a specific component DOM structure
   - Recommendation: Keep `components/TrackcardPreview.vue` as the orchestrator file; the Playwright route uses the full page URL not a direct component import
