# Phase 0.5: Garage S3 Storage — Context

**Gathered:** 2026-04-27
**Status:** Ready for planning

<domain>
## Phase Boundary

Replace MinIO with Garage as the S3-compatible object storage layer in docker-compose.yml. No application code changes — `minio-go` client is S3-API-compatible with Garage. Only infrastructure configuration changes.

**Scope:**
- Swap `storage` service from MinIO to Garage in docker-compose.yml
- Add `S3_REGION` env var (Garage requires explicit region, MinIO did not)
- Update Go config to accept `S3_*` env vars (clean break from MINIO_* naming)
- Update backup/restore scripts to use `aws s3` CLI instead of `mc`
- Update .env.example with S3_* variable names
- Ensure health check works with Garage

**Out of scope:**
- No data migration path from existing MinIO deployments (fresh-start only)
- No application code changes (S3 API compatibility handles this)
- No admin console exposure

</domain>

<decisions>
## Implementation Decisions

### Env var naming — S3_* only (clean break)
- `S3_ENDPOINT`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_BUCKET`, `S3_REGION`
- `S3_PUBLIC_ENDPOINT` for presigned URL base (like current MINIO_PUBLIC_ENDPOINT)
- `S3_USE_SSL` for TLS mode
- MINIO_* vars are removed from docs and .env.example — clean break
- Go config struct fields renamed: `S3Endpoint`, `S3AccessKey`, `S3SecretKey`, `S3Bucket`, `S3Region`, `S3PublicEndpoint`, `S3UseSSL`
- No backward aliases — fresh deployment only

### Storage health check — no code change needed
- Garage supports HeadBucket (✅ Implemented per S3 compat page)
- Existing `HealthCheck()` in storage.go that calls `BucketExists` will work with Garage
- No changes needed to `api/internal/platform/storage/storage.go`

### Docker Compose service replacement
- `storage` service: replace `image: minio/minio:latest` with Garage
- Garage Docker image: `dxflrs/garage:v2.1.0` (from quick start docs)
- Ports: S3 API on 3900 (not 9000), no console exposed externally
- No admin UI port exposed (recommendation: don't expose)
- Volume mount for data directory persists between restarts
- Health check: use `curl -f http://localhost:3900/` or `wget -q -O- http://localhost:3900/` (Garage has no `mc` CLI in container)

### Region requirement
- Garage requires explicit `s3_region` in config — no default
- Add `S3_REGION` env var, required (no default like MinIO had)
- Default region value: `garage` (per Garage quick start example)

### Presigned URLs
- Garage implements presigned URLs (✅ per S3 compat page)
- No changes needed — `PresignedGetObject` in storage.go works with Garage

### Backup/restore scripts — aws s3 CLI
- Use `aws s3` CLI (standard, cross-platform, no Garage-specific deps)
- `aws s3 ls s3://bucket/` to list objects
- `aws s3 sync s3://bucket/ ./local-dir/` for backup mirror
- Remove `mc mirror` commands from scripts/backup.sh and scripts/restore.sh
- Both scripts document the Garage endpoint via `AWS_ENDPOINT_URL` env var

### No console/admin UI exposure
- Garage admin API on port 3903, web UI on 3902 — not exposed externally
- Internal-only for advanced debugging if needed
- Users interact via S3 API (existing client behavior unchanged)

### Claude's Discretion
- Exact docker-compose health check command for Garage (probe 3900 port)
- Volume naming for Garage data directories
- Whether to use `--network host` or explicit port mappings in docker-compose
- Resource limits (memory/CPU) for Garage service

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets

- `api/internal/platform/storage/storage.go`: Already wraps `minio.Client`. The S3 API compatibility means all methods (PutObject, GetObject, StatObject, PresignedGetObject, RemoveObject) work with Garage without changes. No code changes needed in the Go storage package.
- `api/internal/platform/config/config.go`: Config struct with envconfig tags. Will need MINIO_* → S3_* renaming. Region was optional in MinIO (no required tag) but becomes required for Garage.
- `api/internal/health/handler.go`: Calls `storage.HealthCheck()` — this works with Garage since HeadBucket is implemented.

### Integration Points

- `docker-compose.yml`: `storage` service definition needs full replacement. API service env vars need S3_* rename. DB service unchanged.
- `scripts/backup.sh`: Uses `mc mirror` for MinIO — needs replacement with `aws s3 sync`. Also needs `AWS_ENDPOINT_URL` set to Garage endpoint.
- `scripts/restore.sh`: Same as backup — needs `aws s3` CLI replacement.
- `.env.example`: MINIO_* vars → S3_* vars, add S3_REGION.

### Established Patterns

- Internal endpoint (Docker network `storage:3900`) vs public endpoint (browser-facing `MINIO_PUBLIC_ENDPOINT`) — same pattern applies for Garage
- Health check in docker-compose uses HTTP probe to storage port — Garage supports this on 3900
- Bucket auto-creation on startup via `EnsureBucket()` — works with Garage

</code_context>

<specifics>
## Specific Ideas

### Garage Docker quick start (used as reference)
```yaml
# Docker run for Garage
docker run \
  -d \
  --name garaged \
  -p 3900:3900 -p 3901:3901 -p 3902:3902 -p 3903:3903 \
  -v /path/to/garage.toml:/etc/garage.toml \
  -v /path/to/garage/meta:/var/lib/garage/meta \
  -v /path/to/garage/data:/var/lib/garage/data \
  dxflrs/garage:v2.1.0
```
Ports: 3900=S3 API, 3901=RPC, 3902=web, 3903=admin

### Garage TOML config structure (for reference)
```toml
metadata_dir = "/tmp/meta"
data_dir = "/tmp/data"
db_engine = "sqlite"
replication_factor = 1
rpc_bind_addr = "[::]:3901"
rpc_public_addr = "127.0.0.1:3901"
rpc_secret = "..."

[s3_api]
s3_region = "garage"
api_bind_addr = "[::]:3900"
root_domain = ".s3.garage.localhost"
```

### Garage S3 compatibility confirmed
All core endpoints implemented: CreateBucket, DeleteBucket, HeadBucket, ListBuckets, PutObject, GetObject, DeleteObject, CopyObject, Multipart upload, Presigned URLs ✅

### aws s3 CLI usage with Garage
```bash
export AWS_ACCESS_KEY_ID=<key-id>
export AWS_SECRET_ACCESS_KEY=<secret>
export AWS_DEFAULT_REGION='garage'
export AWS_ENDPOINT_URL='http://localhost:3900'
aws s3 ls
aws s3 sync s3://klubhub-dj/ ./backup/
```

</specifics>
