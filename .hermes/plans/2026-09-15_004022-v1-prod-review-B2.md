# B.2 Spec-Compliance Review

## Scope

Plan task **B.2 — Healthcheck that actually executes**, fixing the four audit
findings cited in the plan header:

1. `docker-compose.yml:75–80` `wget` against a `FROM scratch` image
   (no shell, no wget).
2. `api/internal/platform/http/health.go:84–98` always returns HTTP 200.
3. `api/internal/platform/storage/storage.go:68–72` discards the
   `exists` bool from `BucketExists`.
4. `api/Dockerfile` `FROM scratch` cannot perform socket/TLS for outbound
   probes once we switch to a binary-driven healthcheck.

## Spec requirements (verbatim, plan §B.2)

> - Modify `api/internal/platform/http/health.go:84–98`: return HTTP 503 when
>   DB or storage subsystems are not ready. Track returned bool from storage
>   health check (currently discarded at `storage.go:68–72`).
> - Modify `api/Dockerfile`: replace `FROM scratch` with
>   `FROM gcr.io/distroless/static-debian12:nonroot` so the binary can
>   perform `socket(...)` while remaining no-shell and no-package-manager.
> - Update `docker-compose.yml` healthcheck to `CMD ["/api", "-healthcheck"]`
>   (add a CLI flag in `cmd/api/main.go` that exits 0 if /health 200,
>   non-zero otherwise).
> - **Tests:** `cmd/api/main.go` test that asserts `-healthcheck=1` causes
>   process exit with 0 on healthy, non-zero otherwise; existing platform/http
>   health tests extended.

## Out-of-scope observations (NOT B.2 blockers; flagging for parent)

These pre-existed and are explicitly allocated to other plan tasks. They are
noted here so the parent agent can route them to the right reviewer.

1. **`docker-compose.yml:45` `DATABASE_URL` literal `***`** — predates this PR.
   Plan §C.3 covers this ("current literal `***` must be replaced with
   `${POSTGRES_PASSWORD:?…}` placeholder"). Rendered output currently shows
   `DATABASE_URL: postgres://klubhub:***@db:5432/klubhub?sslmode=disable`,
   which means the API container, if started today, would try to connect with
   the literal password `***`. This is a **release blocker** for any non-test
   compose-up, but it is not a regression introduced by B.2. **Recommended
   action:** ensure C.3 lands before G.1 (release-day dry run).

2. **`api/internal/platform/config/config.go` does not implement `_FILE` env
   reading.** Plan §C.3 says production compose will pass secrets as
   `*_FILE` env vars "that the API already supports (verify in
   `api/internal/platform/config/config.go`)". That verification reveals
   the API does **not** yet support `_FILE` — `envconfig.Process` reads only
   direct env vars. This means distroless nonroot + Docker `secrets:` +
   `_FILE` env wiring is a real gap, not just a verification step. **Out of
   scope for B.2**, but the C.3 reviewer needs to either (a) extend
   `config.go` to walk `*_FILE` first and fall back to direct, or
   (b) document that `_FILE` env wiring is a follow-up. The distroless
   `:nonroot` base **does** ship with the standard `getenv()` syscall,
   so distroless is not the blocker — the gap is purely in the Go loader.

3. **`docker-compose.yml` does not declare `stop_grace_period`.** Plan §B.3
   covers adding `stop_grace_period: 30s`. Out of scope for B.2.

4. **Base image not pinned by digest.** Plan §C.4 covers pinning
   `gcr.io/distroless/static-debian12:nonroot` to `@sha256:…`. Out of scope
   for B.2 but noted in the Dockerfile comment block ("NOTE: Task C.4 will
   pin this base image by digest.").

## Risk assessment for B.2 specifically

- **Behavior parity:** the previous healthcheck used `wget -q -O-` against
  `/api/v1/health` and relied on the exit code. The new path uses an
  HTTP client and reads `resp.StatusCode`. Both reject non-200 responses,
  so the contract is preserved.
- **Bootstrap timing:** the spec uses `start_period: 10s`. With the new
  binary probe and distroless image, the cold-start window is comparable to
  before (Go binary load + DB ping ≈ 1–3 s typical). No regression expected.
- **Garage bucket bootstrap:** the bucket-missing error path now
  correctly returns 503. Combined with the planned `scripts/garage-bootstrap.sh`
  (C.2), the API will not report healthy until bootstrap completes. This is
  the intended behavior — accept.
- **Healthcheck timeout budget:** `healthcheckTimeout = 5 * time.Second` in
  `main.go:35` is generous vs. the DB ping budget (400 ms in
  `health.go:43`). Combined worst case: ~1 s. Compose timeout is 5 s with
  3 retries; comfortable margin.
