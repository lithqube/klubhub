# KlubHub DJ v1.2.0 — E-invoicing, document archive, Rider Templates

Released 2026-10-03. The full list of changes is in
[`CHANGELOG.md`](../../CHANGELOG.md#120---2026-10-03); this page is the
operator's view: what is new, what to do when upgrading, and how the image is
published.

A project by EUN Records (Berlin).

## Headline

- **E-invoicing.** Issued invoices and credit notes export as **Factur-X
  (ZUGFeRD)** and **XRechnung** (CII and UBL). Every file is checked against
  the EN 16931 and XRechnung rules by KlubHub's own engine before it is
  returned, and missing data is reported field by field. CI also runs the
  official KoSIT validator over the golden files. The generator is a pinned,
  internal-only `einvoice` service in both Compose files.
- **Archive of issued documents.** Issuing archives the PDF as issued and, when
  it can be exported, the validated XML and its report. The database refuses to
  change or delete a stored document. Browse and download them from the ARCHIVE
  panel of the invoice sheet.
- **Send by email.** An issued invoice or credit note goes to its customer with
  the archived PDF and e-invoice attached; replies reach the DJ (reply-to).
- **Receipts on expenses**, EN 16931 invoice fields, editable invoice lines,
  PDF download, and German legal notes.
- **Rider Templates (Phase 4.5).** Reusable rider templates, attached to gigs as
  per-gig copies, exported as PDF.
- **Tracklist editor.** Manual tracks, drag-to-reorder, rename, gig linking,
  and hidden-gem / unreleased / vinyl-or-digital markers on the exported card.
- **Resident Advisor import is open source and on by default.**
- **Dashboard** built from real data with honest loading and failure states.

Everything above is free and open source (MIT). Tax and VAT *calculation*
remains out of scope (FIN-10); the German legal wording is common practice, not
tax advice, so have a Steuerberater confirm it.

## Upgrading from 1.1.0

1. **Back up** Postgres and Garage first ([Operations](../OPERATIONS.md#backup-and-restore)).
   Migrations may make an image-only rollback unsafe.
2. Select the new image. `docker-compose.prod.yml` now defaults to
   `IMAGE_TAG=v1.2.0`; see [container images](../container-images.md) for
   publishing and verifying the tag. Rerun `bash scripts/setup.sh prod` with
   your existing configuration.
3. Migrations **023–032** run on start (ledger, storage-key renames, rider
   templates, track markers, e-invoice fields, receipts, document kinds with
   an immutability trigger, email reply-to).
4. **Set `CORS_ORIGIN`** if you reach the app by a LAN IP or another hostname.
   Writes to `/api/v1` from a non-loopback host that is not `CORS_ORIGIN` now
   return 403 (DNS-rebinding protection; not authentication).
5. **Archive older invoices**, which are not archived automatically:

   ```bash
   docker compose exec app /api -backfill-archive -dry-run
   docker compose exec app /api -backfill-archive
   ```

   Backfilled documents are marked `uploaded_by: backfill` because they are
   rendered now, not the file produced at the time.
6. **E-invoice sidecar.** The new `einvoice` service is amd64-only (emulated on
   Apple Silicon) and must stay on the internal network with no published
   port. Unset `EINVOICE_URL` to turn export off (the routes answer 503).
7. **API clients:** `imageMinioPath` is now `imageStorageKey` (scheduled
   posts) and `minioPath` is now `garageObjectKey` (EPK exports).
8. **Resident Advisor import** is now on. Set `FEATURE_RA_IMPORT=false`
   (installer: `--no-ra-import`) to turn it off.
9. Read `scripts/RESTORE.md` before your next restore; the restore script was
   rewritten and has a drill.

See [`SELF-HOSTING.md`](../SELF-HOSTING.md), [`INVOICING.md`](../INVOICING.md)
and [`CONFIGURATION.md`](../CONFIGURATION.md).

## Publishing the image (maintainers)

Images are not published on tag push. Run the **Publish KlubHub DJ container
image** workflow manually with `tag_override=v1.2.0`, then verify the manifest
(single `linux/arm64` descriptor), Trivy, SBOM and cosign results, and
`docker compose ... exec -T app /api -version` printing `1.2.0`. Only then tag
`v1.2.0` on the merge commit.
