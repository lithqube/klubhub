# KlubHub DJ v1.0.1 — Release Notes

## Headline

**Runtime, CI, and onboarding hardening.**

A point release that ships the runtime contract fixes, the GitHub Pages
env-binding fix, the Plunk newsletter integration, **and** the live
module wiring that landed in PRs #5, #7, #9, #10, #11, #12, and #13
between the v1.0.0 tag and this cut. **No breaking changes.** The
Compose service, GHCR image, the Go API, and the Nuxt site all behave
the same at runtime; this release fixes how the project is **built,
deployed, and onboarded**, and replaces the module-level mocks with
real contract calls.

## What ships

### Runtime contract

- **Compose service rename**: `api` → `app`. Consistent with the
  per-product naming convention that future KlubHub products (Promoter,
  Label) will follow.
- **Dev compose** (`docker-compose.yml`) builds locally, exposes
  `127.0.0.1:8080` to the host, sets `SERVE_FRONTEND=false`, and
  expects the Nuxt dev server to run on the host at `:4200`.
- **Prod compose** (`docker-compose.prod.yml`) pulls
  `ghcr.io/lithqube/klubhub-dj-api:${IMAGE_TAG:-v1.0.1}`, sets
  `SERVE_FRONTEND=true`, and serves the static site at `/`.
- **Dev overlay** (`docker-compose.dev.yml`) adds the Garage admin
  port `127.0.0.1:39002:3903` for direct S3-compatible inspection.

### GitHub Pages + Plunk

- `pages.yml` build job binds to the `github-pages` environment so it
  can read `PLUNK_PUBLIC_KEY` from environment secrets. PR builds use
  the inline placeholder `pk_ci_pr_preview_only_do_not_subscribe`.
- The static site fails closed if the public key is missing, the
  placeholder, or the wrong prefix (`sk_*`). Build errors are clear
  and immediate.
- Newsletter form is mobile-responsive.
- Static site body copy uses commas in place of em dashes for
  consistent rendering across email and RSS clients.

### Documentation

- `docs/PRODUCTION.md` — agent-first production runbook (12-row
  verification matrix, upgrade procedure, nginx, backup/restore,
  secret rotation, common failures, "For humans" section).
- `apps/site/emails/README.md` — Kinetic-HUD email templates
  (`welcome.html`, `onboarding.html`) with the full Plunk workflow
  contract documented.
- `.hermes.md` + `.agents/skills/klubhub-dev/` — repo-wide context
  and a project-specific skill that encodes the operating procedures
  (Compose contract, Plunk secrets, GHCR naming, Nx project names,
  em dash policy).

### Module wiring (live API)

The gig, epk, tracklist, and social modules now talk to the live Go
API instead of local mocks. Stores (`apps/dj/app/stores/{gig,epk,
tracklist,social}.ts`), composables (`useTracklist.ts`), and pages
(`index.vue`, `finance.vue`, `social.vue`) consume the real fetch
endpoints. New contract tests at
`api/internal/{gig,epk,tracklist}/contract_test.go` cover the
handler-to-service boundary.

## What does NOT ship in v1.0.1

- **linux/amd64 images** — still deferred. arm64 only.
- **GHCR image `v1.0.1`** — published post-merge via:
  ```bash
  gh workflow run containers.dj.yml --ref main -f tag=v1.0.1
  ```
  The default `IMAGE_TAG=v1.0.1` will pull successfully once that
  workflow run completes.
- **Plunk workflow trigger rename** — an operator action in the Plunk
  UI is required. Open Workflows → `klubhub · welcome onboard` →
  Trigger node → change `contact.subscribed` to `klubhub.subscribed`.
  Zero executions have run, so the rename is allowed.
- **Plunk onboarding template body fix** — the live Plunk copy has a
  stray `;` in its footer paragraph. Edit the Plunk template to match
  the local `apps/site/emails/onboarding.html`.

## Verify

After the GHCR image is published:

```bash
# Pull the new image and confirm it exists
docker pull ghcr.io/lithqube/klubhub-dj-api:v1.0.1

# Pull the production compose
curl -fsSL https://raw.githubusercontent.com/lithqube/klubhub-dj/v1.0.1/docker-compose.prod.yml \
  -o docker-compose.prod.yml

# Bring up the stack
docker compose -f docker-compose.prod.yml --env-file .env up -d --wait

# Health check
curl -fsS http://127.0.0.1:8080/api/v1/health
```

Expected: `{"status":"ok"}` with HTTP 200.

## Operator notes

- **Production upgrade from v1.0.0**: stop the v1.0.0 stack,
  pull the v1.0.1 image (`docker compose pull`), and bring it back up
  with `IMAGE_TAG=v1.0.1`. The data volumes persist across the upgrade;
  no database migration runs between v1.0.0 and v1.0.1.
- **Plunk secret rotation**: see `apps/site/emails/README.md` and
  `.agents/skills/klubhub-dev/references/plunk-secrets.md`. The PK
  rotates by updating the GitHub `github-pages` environment secret
  and triggering a `pages.yml` run on `main`. The SK rotates by
  redeploying with the new secret file mounted at
  `/etc/klubhub/secrets/plunk_secret_key` on the host.
- **Renaming the Plunk workflow trigger**: required post-merge. Until
  this is done, the welcome email will not fire on newsletter
  signups. The MCP `track_event` tool can fire
  `event: 'klubhub.subscribed'` manually for a quick smoke test.
