# KlubHub DJ v1.0.0 — Release Notes

## Headline

**First public open-source release.**

KlubHub DJ is a self-hosted career-management platform for independent
DJs. v1.0.0 ships eight modules (Tracklist Image Generator, Social
Media Scheduler, EPK / Press Kit Builder, Gig Tracker, plus their
dependencies) on `linux/arm64` Docker images published to GHCR.

## What ships

- **8 modules**: Infrastructure, Tracklist Image Generator, Design System
  (Kinetic HUD), Social Media Scheduler, EPK, Gig Tracker.
- **Container images**: `ghcr.io/lithqube/klubhub-dj/api:v1.0.0` and
  `…/frontend:v1.0.0` (linux/arm64 only).
- **Production Compose**: `docker-compose.prod.yml` with `secrets:` block,
  resource limits, and `stop_grace_period` aligned to graceful
  shutdown.

## What does NOT ship in v1.0.0

- **linux/amd64 images** — deferred to a point release. amd64 hosts must
  run a QEMU-emulated container or wait.
- **Phase 4 (Gig Tracker) gaps** — moved to v1.0.1: tracklist-to-gig
  linking, dedicated venues/contacts list pages, and the
  copy-from-previous-gig venue/contact record preservation.
- **Modules 4.5+ (Rider Templates, Finance, Release Planner, Tour Manager,
  Dashboard)** — all `Planned` in the roadmap; see
  [`docs/v1-release-plan.md`](docs/v1-release-plan.md).
- **Multi-platform social scheduling (TikTok, X, Facebook), hosted EPK
  pages, AI caption generation** — KlubHub Cloud PRO features per the
  v2 SaaS migration plan.

## Highlights

- **Calendar/PDF bearer authentication** migrated from a hard-coded
  literal to an env-injected, constant-time-comparison secret. Old
  placeholder URLs no longer authenticate.
- **OAuth state management** is now server-side, single-use, cookie-bound,
  with a 10-minute TTL. Replays, mismatches, and expiries all fail
  closed without touching the DB.
- **Transport error sanitization** for Instagram OAuth. `client_id`,
  `client_secret`, and `access_token` values never appear in logs or
  persisted retry errors.
- **Request body cap middleware** (1 MiB default; per-route override)
  with `*_FILE` env-var support for Docker `secrets:`-mounted
  credentials.
- **Strict artwork fetcher**: 10-second timeout, 5 MiB body cap, no
  redirects (SSRF defense).

## Known limitations

- **No authentication on management routes.** Self-hosted single-user
  design. If exposing the stack beyond `127.0.0.1`, put a reverse proxy
  with auth in front. See [`SECURITY.md`](SECURITY.md).
- **Build-time mock-handler exclusion.** Dev and staging builds keep
  the in-tree mock API handlers at `apps/dj/server/api/v1/`; production
  builds rename the directory to `v1.mock/` for the duration of the
  build and restore it after. The rename is reversible; if you see a
  `v1.mock/` left over after a crashed build, run
  `mv apps/dj/server/api/v1.mock apps/dj/server/api/v1`.
- **Calendar token rotation is breaking** for any external calendar
  client that copied an `?secret=…` URL. Document the rotation in
  `docs/CONFIGURATION.md` before rotating.

## Upgrade path

Fresh install:

```bash
mkdir -p ./secrets && chmod 0700 ./secrets
for k in postgres_password garage_rpc_secret garage_admin_token \
         token_encryption_key ical_secret; do
  openssl rand -hex 32 > "./secrets/$k"
  chmod 600 "./secrets/$k"
done

curl -fsSL https://raw.githubusercontent.com/lithqube/klubhub-dj/v1.0.0/docker-compose.prod.yml \
  -o docker-compose.prod.yml
curl -fsSL https://raw.githubusercontent.com/lithqube/klubhub-dj/v1.0.0/.env.example -o .env.example
cp .env.example .env

docker compose -f docker-compose.prod.yml pull
docker compose -f docker-compose.prod.yml up -d

bash scripts/garage-bootstrap.sh -f docker-compose.prod.yml -p klubhub
# (capture S3 keys into ./secrets/, then:)
docker compose -f docker-compose.prod.yml restart api
```

From pre-1.0 (alpha):

- Migrations run automatically on API startup. The five `005b..005f_*.sql`
  migrations are renamed to `006_venues.sql` through `010_tracklist_gigs.sql`
  to satisfy the Goose integer-prefix parser; there is no v0.9 install
  path, so this is a fresh-database-only requirement.

## Verify

```bash
docker compose -f docker-compose.prod.yml exec api /api -healthcheck
curl -fs http://127.0.0.1:8080/api/v1/health
```

A healthy response is `{"status":"healthy", "integrations": {...}, "migrations_ok": true}`.
