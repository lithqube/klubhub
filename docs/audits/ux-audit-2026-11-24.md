# UX audit 002: DJ, Promoter and landing site (2026-11-24)

## Status (2026-11-25)

All seven P0 issues are fixed in the working tree: DJ 1–4 and Promoter 1–3. Each has a unit test except DJ 4 (checked in the browser). End-to-end tests have not been run. Two choices differ from the fix column: DJ 3 removes ROOM / DETAILS, and DJ 4 keeps the five bar items and adds MORE for the other three. The P1 and P2 issues are open.

## How this was checked

- **DJ:** public demo (`klubhub.io/demo`, built from `main`) at 375px and 1280px, all 8 screens; DOM probes for names, labels, headings, target size, text size and contrast in both themes.
- **Promoter:** local dev with mock data at 375px, 8 screens probed.
- **Site:** local build at 375px and 1280px.
- **Code:** one read-only reviewer per app.
- **Verified** = I confirmed it in code or in the browser. **Reviewer** = a code reviewer read the path; I did not re-check it. Nothing was reproduced against a real backend.
- Not covered: Promoter light theme, settings/recovery, report, export, venue and account pages; DJ billing profile, receipts, calendar views.

## KlubHub DJ

### Inferred intent
- Primary user: an independent DJ running their own bookings, content and money, often on a phone.
- Primary action: get the next gig handled (record it, post about it, invoice it).
- Worst case designed against: losing or silently changing something that goes public or gets paid.

### Issues

| # | Sev | Issue | Why it matters | Fix | Source |
|---|---|---|---|---|---|

| 2 | P0 | A failed EPK autosave is dropped (`useEpkAutosave.ts` clears `pending` before saving); the next success overwrites the field while the header says saved | Typed bio text disappears | Merge the failed patch back; serialize saves | Verified |
| 3 | P0 | "CREATE NEW VENUE" only closes the list, so a typed venue is not saved; ROOM / DETAILS is never sent (no such field in the API) | Gig is stored with the wrong venue, or details vanish | Emit the typed value; remove ROOM / DETAILS or persist it | Verified |

### Fix first

**1. Social edit (issue 1).** In `UpdatePost` (service), fall back to the existing key; in the card, format in the post's zone:

```go
if req.ImageStorageKey == "" {
	req.ImageStorageKey = post.ImageStorageKey
}
```

```ts
const toLocalInput = (utc: string, tz: string) =>
  new Intl.DateTimeFormat('sv-SE', { timeZone: tz, dateStyle: 'short', timeStyle: 'short' })
    .format(new Date(utc)).replace(' ', 'T')
```

**2. EPK autosave (issue 2).**

```ts
const patch = pending
pending = {}
try { await store.updateContent(patch) }
catch { pending = { ...patch, ...pending } } // newer keystrokes win
```

Also stop `updateContent` from reseeding fields the user is editing, as `useRiderAutosave` already does.

**3. Venue and mobile nav (issues 3 and 4).** Emit the typed venue from `VenueAutocomplete` on input and clear. For the nav, copy `apps/promoter/app/components/TheBottomNav.vue`: keep DASH, GIGS, SOCIAL, FINANCE and move the rest into MORE.

### What works
- Invoice confirm dialogs state the consequence and require a reason for credit or correction.
- Invoice email needs a second click naming the recipient and says when delivery is still pending.
- Rider autosave keeps failed patches and guards page exit: use it as the model.
- No horizontal page overflow at 375px; no contrast failures detected in either theme.

## KlubHub Promoter

### Inferred intent
- Primary user: a promoter planning events, and door staff on a phone at night with poor signal.
- Primary action: publish an event and admit the right people.
- Worst case designed against: losing check-ins, or telling staff something happened when it did not.

### Issues

| # | Sev | Issue | Why it matters | Fix | Source |
|---|---|---|---|---|---|
| 1 | P0 | A re-login that succeeds but fails to download the bundle clears the vault; the retry finds no bundle and drops unsynced check-ins (`stores/door.ts` `login`) | Door data is lost on bad signal | Fetch the bundle before `create()` and `reset()` | Verified |
| 2 | P0 | The offer composer reports "Offer sent" without reading the returned status; the API answers success with `email_status: failed`; SEND stays enabled | Booker waits for a mail that never left, or sends twice | Check the status; disable until edited | Verified |
| 3 | P0 | A saved local timetable draft has no base version, so saving it overwrites a teammate's newer lineup | Set times silently replaced | Store the base version; block and offer compare | Verified |
| 4 | P1 | Switching event, FORGET and REVOKE can wipe queued door actions without saying so | Lost check-ins | Count the queue; require sync or explicit discard | Reviewer |
| 5 | P1 | A typed order number matches only the order's first ticket | A paying friend shows "already in" | List all tickets of the order | Reviewer |
| 6 | P1 | Failed loads keep the previous event's guests or slots; PIN status reads NOT SET, so GENERATE replaces a live PIN | Acting on the wrong event | Clear on event change; block while unknown | Reviewer |
| 7 | P1 | A failed delete, unsubscribe or retry replaces the whole page with SYSTEM ERROR | Unclear whether it happened; typed input lost | Catch per row and show inline | Reviewer |
| 8 | P1 | The audience CSV import closes before its result is visible | "0 added" looks like success | Keep counts on screen; preview columns | Reviewer |
| 9 | P1 | Typing 01:00 for an overnight set places it on the previous day | Publish blocked or a 26-hour set | Resolve against the event window; show the weekday | Reviewer |
| 10 | P2 | PUBLISH NOW and POSTPONE act on one tap | Accidental publication with no way back to draft | Confirm and disable while running | Reviewer |
| 11 | P2 | At 375px the event header, actions and tabs take about half the screen and the EXPORT tab is off screen with no cue | Content starts low; a section is hidden | Compact header; add a scroll fade | Verified |
| 12 | P2 | Most text on event screens is under 11px; audience search has no label; "Delete segment" is under 24px | Legibility and mis-taps at night | Raise the floor; label; enlarge | Verified |

### Fix first

**1. Door re-login (issue 1).** Download first, replace second:

```ts
phase.value = 'loading'
const fresh = await fetchBundle()   // throws before anything is destroyed
await theVault().create()
reset()
restore(carry); apply(fresh)
```

(`fetchBundle`, `restore` and `apply` are the two halves of today's `downloadBundle`.) Add a test: login succeeds, bundle fails, retry keeps the queue.

**2. Offer status (issue 2).**

```ts
const o = await store.sendOffer(payload)
if (o.email_status === 'failed' || o.email_status === 'bounced') {
  error.value = { error: o.email_error || 'delivery_failed' } as ApiError
  return
}
```

**3. Timetable draft (issue 3).** Persist `{ baseVersion, lineup }`; if `baseVersion !== event.version`, disable SAVE and offer VIEW SAVED, DISCARD MINE or OVERWRITE.

### What works
- Door admit card: two-tap amber admit with a double-tap guard and a distinct "cannot admit" state.
- Erase-now dialog lists what is erased and kept, asks for the typed title and a fresh sign-in.
- Attendee import shows a server dry run before committing.
- Event form explains overnight, DST and time-zone cases in plain words.
- Mobile navigation has a MORE sheet, so every section is reachable.

## Landing site

### Inferred intent
- Primary user: a DJ or promoter deciding whether to try KlubHub.
- Primary action: open the demo or install.
- Worst case designed against: leaving before understanding what it is.

No P0 to P2 issue showed up in the checks run: one `h1`, three clear actions above the fold, no overflow at 375px, no unnamed controls, and the Promoter is labelled "self-hosting preview". One P3: the hero paragraph speaks only about a DJ career although two products are listed. Contrast and screen reader order were not checked here.
